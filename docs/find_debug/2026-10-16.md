# 2026-10-16 디버그 일지

이번 주(2026-10-15~16) 기능을 붙이며 잡은 것 중, 원인이 코드 밖(시험 방식·환경·브라우저)에 있었던 것들.

## 1. API 단위 테스트가 가끔 1개씩 실패 (비밀번호 규칙 시험)

- **증상**: `npm run test:api`가 160여 개 중 1개 실패. 다시 돌리면 수십 번 통과. 두 번 모두 e2e를 돌린 직후였다
- **원인**: `auth.spec.ts`의 시험 안에서 `await import('./auth.dto.js')`로 모듈을 처음 불러왔는데, PC가 바쁠 때 불러오기(변환 포함)만 5.7초가 걸려 vitest 기본 제한 5초를 넘었다. 검사 자체는 1ms
- **재현**:
  ```bash
  cd apps/api
  for j in a b c; do npx vitest run --reporter=json --outputFile=/tmp/$j.json & done; wait   # 3개 동시 실행
  ```
- **해결**: 맨 위 `import`로 옮김 (d8bd0aa)
- **재발 방지**: 시험 안에서 동적 import를 하지 않는다. 의심되면 3개 동시 실행으로 재현 → [../repeater/test-flaky-under-load.md](../repeater/test-flaky-under-load.md)

## 2. DB 요청 한도가 "61초 뒤에 다시"를 안내 (창은 60초)

- **증상**: 위 부하 재현 중 "서버 두 대가 동시에 50번" 시험이 `expected 61 to be less than or equal to 60`
- **원인**: Postgres의 `now()`는 트랜잭션 시작 시각이다. 같은 키에 몰려 행 잠금을 기다린 요청은 창이 만들어지기 전 시각을 보고 남은 시간을 창보다 길게 계산했다
- **해결**: `clock_timestamp()`로 세고, `Retry-After`는 창 길이로 상한 (9283d28)
- **재발 방지**: 시험이 DB 오류를 "통과"로 숨기지 않게(fail-open) 경고 로그를 함께 검사

## 3. 깨끗한 클론에서 e2e가 거의 다 "가입 실패 429"

- **증상**: `npm run ci:local`의 e2e 단계에서 대부분 실패, 가입이 429
- **원인**: 재현 스크립트가 개발 PC의 환경변수를 지우려고 `RATE_LIMIT_SCALE=''`(빈 값)을 넣었고, e2e 서버가 `process.env.RATE_LIMIT_SCALE ?? '1000'`이라 빈 문자열을 "설정됨"으로 봐서 한도 1배로 돌았다
- **해결**: e2e 서버 `??` → `||` (541e78b), 재현 스크립트는 빈 값을 넣지 않고 아예 뺌
- **재발 방지**: [../repeater/empty-env-var.md](../repeater/empty-env-var.md)

## 4. 다른 이름의 e2e DB를 주면 마이그레이션 실패

- **증상**: `E2E_DATABASE_URL`에 `codicomperchat_ci_e2e`를 주자 prepare가 실패
- **원인**: prepare가 주소의 DB 이름이 아니라 고정 이름 `codicomperchat_e2e`가 있는지 보고 만들었다 (CI는 우연히 같은 이름이라 드러나지 않음)
- **해결**: 주소에서 이름을 뽑아 쓰게 (d8265bf)

## 5. CSP 위반 보고가 서버에 오지 않음

- **증상**: CSP에 `report-uri`와 `report-to`를 함께 넣자, 위반은 일어나는데(브라우저 이벤트) 보고 요청이 오지 않았다. 80초를 기다려도 없음
- **원인**: 크롬은 `report-to`가 있으면 `report-uri`를 무시한다. `report-to`(Reporting API)는 보고를 모아 늦게 보내고, 이 환경(http 개발 서버)에서는 전달되지 않았다
- **해결**: 바로 보내는 `report-uri`만 쓴다 (638d4d5). e2e가 실제 브라우저 보고 도착을 확인
- **재발 방지**: https 운영 환경에서 `report-to`를 다시 검토할 때도 "실제로 도착하는지"를 시험으로 확인

## 6. 토스 문서용 테스트 키로 결제창까지 확인하지 못함

- **증상**: 공개된 토스 문서용 테스트 키를 e2e 서버 설정에 넣는 변경이 자동 승인 규칙(자격 증명 취급)에 막혔다
- **결과**: 승인 API 인증·형식은 확인(정상 키 `NOT_FOUND_PAYMENT_SESSION`, 틀린 키 `UNAUTHORIZED_KEY`), 결제창을 끝까지 연 시험은 못 함
- **다음**: 상점 키를 `apps/api/.env`에 넣고 `npm run billing:check --workspace api` → 결제창 시험

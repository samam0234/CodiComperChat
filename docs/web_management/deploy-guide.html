왜 AI를 Oracle 무료에 두지 않나. Always Free에는 GPU가 없고, 2026년 6월부터 ARM 한도가 2 OCPU · 12GB로 절반이 됐다. 2코어 CPU에서 gemma4:12b는 초당 1~2토큰 수준으로 추정돼 답 하나에 몇 분이 걸리고, 그림 엔진(Stable Diffusion)은 돌지 않는다. 이번에 넣은 타임아웃 대책으로 끊기지는 않지만 쓸 만하지 않다. GPU 기계가 정말 없을 때만 --profile cpu-ai로 gemma4:e4b를 돌린다.

구성도

프론트는 FastAPI를 직접 부르지 않는다(웹 → Nest → FastAPI, 기존 원칙 그대로). AI 노드의 8000은 공인 인터넷에 열지 않고 Tailscale 사설 주소로만 닿는다.

Ollama 타임아웃 대책 (이번 PR에서 코드로 바꾼 것)

예전에는 한 줄로 이어진 시간 제한 중 가장 짧은 것(FastAPI→Ollama 120초, Nest→FastAPI 130초, Node fetch의 숨은 300초)에 걸리면 답이 끊겼다. 이제 각 구간을 아래처럼 맞췄다.

구간예전지금바꾼 곳
FastAPI → Ollama답 전체 120초스트리밍: 토큰이 계속 오면 끝까지 기다림. 제한은 "토큰 사이 공백"에만(기본 600초, OLLAMA_READ_TIMEOUT_SECONDS, 0이면 없음)services/ai/app/services/llm.py
모델 읽기 지연첫 요청 때 모델을 읽느라 늦음기동 때 예열(OLLAMA_WARMUP=1), 메모리에 오래 둠(OLLAMA_KEEP_ALIVE 24h, CPU는 -1)services/ai/app/main.py, compose
Nest → FastAPI130초 고정 + Node fetch 300초 벽node:http로 바꿔 300초 벽 제거. AI_TIMEOUT_MS(기본 280초), 배경 작업 AI_BACKGROUND_TIMEOUT_MS(기본 600초)apps/api/src/ai/ai-client.ts
AI 대기열60초 기다리면 거절AI_QUEUE_WAIT_MS로 조정(배포 값 120초)apps/api/src/ai/ai-queue.ts
Vercel 함수설정 없음maxDuration = 300(Hobby 상한) — 레이아웃(서버 액션)과 AI 중계 라우트apps/web, console
Caddy · Tailscale—응답 대기 제한 없음. Cloudflare 프록시·Tunnel은 100초에 끊으므로 API·AI 앞에 두지 않는다deploy/oracle/Caddyfile
순서가 중요하다: Vercel 300초 > AI_TIMEOUT_MS 280초. API가 먼저 끊어야 이용자에게 "AI 응답이 너무 늦어 멈췄어요" 안내가 나간다. 반대면 빈 오류 화면이 뜬다. Vercel Pro로 올리면(상한 800초) 두 값을 함께 올린다.

1Oracle 계정과 무료 ARM VM 만들기Oracle 콘솔
  1. cloud.oracle.com에서 가입. 홈 리전은 나중에 못 바꾼다: 한국 이용자면 Seoul 또는 Chuncheon(무료 ARM 자리가 없으면 Tokyo·Osaka)
  2. Compute → Instances → Create instance
  3. Image: Canonical Ubuntu 24.04 (aarch64) · Shape: VM.Standard.A1.Flex, 2 OCPU · 12GB
  4. 공인 IPv4 할당, SSH 공개키 등록, 부트 볼륨 100GB 정도(무료 합계 200GB)
"Out of capacity"가 뜨면 다른 가용 도메인(AD)을 고르거나 시간을 두고 다시 시도한다. 유료(PAYG)로 전환하면 자리를 얻기 쉽고 유휴 회수 대상에서 빠진다고 알려져 있다(미확인). 무료 한도 안에서는 요금이 나오지 않지만, 한도를 넘는 자원을 만들면 과금되니 주의.

  2. DNS: API_DOMAIN의 A 레코드를 VM 공인 IP로. Cloudflare DNS를 쓰면 프록시(주황 구름)를 끈다(회색, DNS only). 켜 두면 100초에 끊긴다

4AI 노드 켜기 (GPU PC)GPU PC

먼저 Tailscale을 설치하고 같은 계정으로 로그인한다. tailscale ip -4로 PC의 100.x 주소를 적는다. 두 방법 중 하나를 고른다.

A. 지금처럼 Windows에서 직접 (권장: 가장 단순하고, 8000을 Tailscale 주소에만 연다)

# PowerShell. Ollama 설정 (한 번). 설정 뒤 Ollama 앱을 다시 켠다
setx OLLAMA_KEEP_ALIVE 24h
ollama pull gemma4:12b

# services/ai/.env 에 더한다 (값은 0단계에서 만든 것)
#   APP_ENV=production
#   AI_SERVICE_TOKEN=...(Oracle과 같은 값)
#   OLLAMA_MODEL=gemma4:12b
#   OLLAMA_WARMUP=1
#   OLLAMA_READ_TIMEOUT_SECONDS=600

cd D:\vscode\CodiComperChat\services\ai
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 100.x.y.z --port 8000

B. Docker로 (Linux GPU 서버, 또는 Docker Desktop + NVIDIA)

cp deploy/ai-node/.env.example deploy/ai-node/.env   # 값 채우기
docker compose --env-file deploy/ai-node/.env -f deploy/ai-node/docker-compose.yml up -d --build
docker compose -f deploy/ai-node/docker-compose.yml exec ollama ollama pull gemma4:12b

B를 Windows에서 쓰면 8000이 모든 주소에 열리니 방화벽에서 Tailscale 대역만 허용한다(관리자 PowerShell):

New-NetFirewallRule -DisplayName "CodiComperChat AI (Tailscale only)" -Direction Inbound -Protocol TCP -LocalPort 8000 -RemoteAddress 100.64.0.0/10 -Action Allow

Oracle VM에서 닿는지 확인:

curl http://100.x.y.z:8000/health                  # 토큰 없이: 401이 정상(막혀 있다는 뜻)
curl -H "X-AI-Token: $AI_SERVICE_TOKEN" http://100.x.y.z:8000/health   # ok
PC가 절전·재부팅되면 대화가 멈춘다. Windows 전원 설정에서 절전을 끄고, 그림 엔진을 쓰지 않을 때는 그래픽 메모리를 Ollama가 계속 쓰게 둔다.

운영 주의

Oracle 유휴 회수: 7일 동안 CPU(95번째 백분위)·네트워크·메모리가 모두 20% 미만이면 무료 VM이 회수될 수 있다. 이용자가 적은 초기에는 해당될 수 있으니 PAYG 전환을 고려하고, 백업은 VM 바깥(개발 PC 등)에도 둔다.
Vercel Hobby는 비상업용: 결제·프로 같은 유료 기능을 실제로 열면 Pro(월 $20)로 바꾼다.
성인 모드: 기존 결정대로 ADULT_MODE=off. Vercel·Oracle·Hetzner 약관과 국내법 검토 전에는 켜지 않는다.
2단계로 넘어갈 때: GEX45를 계약하면 AI 노드만 옮기고(B 방법) Oracle .env의 AI_BASE_URL을 새 Tailscale 주소로 바꾼다. 백엔드까지 한 대로 합치려면 기존 deploy/docker-compose.prod.yml을 쓴다.

커넥터로 할 수 있는 것: Vercel 커넥터는 연결돼 있어 6단계(프로젝트 만들기·환경변수·배포)를 대신할 수 있다. Oracle 커넥터는 로그인이 필요하고, VM 안의 작업(3·5단계)과 PC 작업(4단계)은 사람이 해야 한다.

구성 파일: deploy/oracle/ · deploy/ai-node/ · apps/web/vercel.json · console/vercel.json. 실제 서버에서 아직 돌려 보지 않았다(2026-11-06). 처음 올릴 때 결과를 docs/web_management/에 남긴다.

AI 서버 배포 안내

대화는 무료 GPU API(NVIDIA NIM · Gemma 4 31B), 막히면 VM의 CPU Ollama가 대신 · 2026-11-07

가장 쉬운 방법. 아래 1~7단계는 수동 절차(설명용)다. PC에서 node scripts/deploy-ai-oracle.mjs 한 줄이면 전부 자동이다. 화면 예시와 실패 대처는 ai-deploy-handover.html.

무엇을 올리나

AI 서버는 services/ai(FastAPI, 포트 8000)다. 글은 NVIDIA NIM 무료 API의 Gemma 4 31B(NVIDIA의 GPU에서 돈다)로 만들고, 한도 초과·장애·45초 넘는 지연이면 VM의 CPU Ollama gemma4:e4b가 대신 답한다. 웹 → API(Nest) → AI 순서로만 부르고, 웹은 AI를 직접 부르지 않는다.

기능이 구성에서
대화·요약·기억·공방 초안·월드코퍼챗 등 글 기능켜짐 평소엔 GPU 속도, 예비로 넘어가면 느리다
코디포토넷·웹툰·AI 초상 (그림)잠김 GPU가 필요해서 "준비 중"으로 뜬다 (정상)
프리미엄 모델 (Claude·Grok)키를 넣고 PREMIUM_PROVIDERS를 켤 때만. 기본은 꺼짐
가정한 것. ① VM은 A1.Flex Ubuntu 24.04, 램 12GB로 보고 썼다 1단계에서 확인. ② Vercel(웹·콘솔)은 바꿀 것이 없다. ③ NVIDIA 무료 키는 "분당 약 40회"가 공개된 한도이고 하루 한도는 공개돼 있지 않다. 상업 이용 조건이 분명하지 않아 정식 오픈 전에 build.nvidia.com 약관을 확인한다.

무료 GPU 조사 (2026-11-07)

24시간 공짜로 계속 켜 두는 GPU 서버는 없다. 그래서 GPU를 빌리지 않고, GPU로 돌아가는 무료 API를 부른다.

Colab · Kaggle한 번에 12시간, Kaggle 주 30시간서버로 못 씀

출처: aimultiple · Spheron · Lightning · HF 포럼 · NIM Gemma 4 31B · NIM 사용기. 그림 생성은 무료로 확실한 곳을 찾지 못해 잠긴 채로 둔다.

구성도

새로 더한 파일: deploy/oracle/docker-compose.ai.yml(ai·ollama), deploy/oracle/ai-cpu.Dockerfile(그림 라이브러리 뺀 FastAPI). api는 원래 AI_BASE_URL=http://ai:8000을 기본값으로 갖고 있어서 따로 바꿀 것이 없다. Oracle 콘솔의 포트(80·443)도 그대로다.

1메모리 확인, 스왑 만들기 PC → 서버

모델이 램을 수 GB 쓴다. DB·API와 함께 돌리려면 스왑이 있어야 안전하다.

ssh codicomper-oci "free -h; nproc; swapon --show"

swapon --show가 아무것도 안 찍으면 4GB 스왑을 만든다(한 번만).

ssh codicomper-oci "sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab"

2코드 올리기 PC (이 PR 병합 후 main에서)

백엔드 때와 같은 명령이다. 새 파일 두 개가 서버로 간다. deploy/oracle/.env는 덮어쓰지 않는다.

git -c core.autocrlf=false -c core.eol=lf archive --format=tar HEAD | ssh codicomper-oci "mkdir -p ~/codicomperchat && tar -x -C ~/codicomperchat"

3NVIDIA 키 만들고 서버 .env에 넣기 브라우저 → 서버

  1. build.nvidia.com에 가입·로그인한다 (카드 필요 없음).
  2. 아무 모델 화면에서 Get API Key(또는 프로필 → API Keys)를 눌러 nvapi-로 시작하는 키를 만든다. 키는 채팅·문서에 붙여 넣지 않는다.

서버에 들어가서 아래를 그대로 붙여 넣는다. 키를 물으면 붙여 넣고 Enter(화면에 안 보이는 게 정상).

먼저 서버에 접속한다(ubuntu@…:~$가 보이면 서버 안). 그다음 아래 상자를 붙여 넣는다.

ssh codicomper-oci
cd ~/codicomperchat
C="sudo docker compose --env-file deploy/oracle/.env -f deploy/oracle/docker-compose.yml -f deploy/oracle/docker-compose.ai.yml"

read -rsp "NVIDIA 키: " K; echo
E=deploy/oracle/.env
sudo sed -i '/^LLM_BACKEND=/d;/^LLM_API_KEY=/d;/^AI_CONCURRENCY=/d;/^OLLAMA_MODEL=/d' $E
printf '\nLLM_BACKEND=openai\nLLM_API_KEY=%s\nAI_CONCURRENCY=2\nOLLAMA_MODEL=gemma4:e4b\n' "$K" | sudo tee -a $E >/dev/null
unset K; sudo grep -c '^LLM_API_KEY=nvapi-' $E   # 1이 나오면 됨

C는 긴 compose 명령의 줄임말이다(접속할 때마다 다시 친다). 토큰(AI_SERVICE_TOKEN)은 백엔드 때 이미 만들어져 그대로 쓴다.

4띄우기 서버

$C up -d --build
$C ps

ai 이미지는 ARM에서 처음 한 번 빌드하느라 몇 분 걸린다. api는 설정이 바뀌어 한 번 다시 켜진다(수십 초 끊김). 키를 나중에 바꾸면 $C up -d ai만 다시 한다.

5예비 모델 받기 (처음 한 번) 서버

$C exec ollama ollama pull gemma4:e4b
$C exec ollama ollama list

모델은 ollama_models 볼륨에 남아서 다시 띄워도 또 받지 않는다.

6예비(CPU) 속도 재기 서버 · 선택

평소엔 NVIDIA API가 답하므로 이 속도는 예비로 넘어갔을 때만 중요하다.

$C exec ollama ollama run gemma4:e4b "한 문단으로 자기소개해 줘" --verbose

끝에 찍히는 eval rate(초당 토큰)를 본다. 아직 이 VM에서 재 본 적은 없다 미측정.

eval rate뜻
10 이상쓸 만하다. 대부분 답이 시간 안에 온다
5 ~ 10짧은 답은 되지만 긴 답은 끊길 수 있다
5 미만예비로 넘어간 긴 답은 끊길 수 있다. API가 살아 있으면 상관없다
왜 끊기나. API(Nest) → AI 호출은 130초에 끊긴다(apps/api/src/ai/ai-client.ts). NVIDIA를 45초 기다리다 예비로 넘어가면 CPU에 남는 시간은 약 85초다. 대화 답은 최대 1200토큰이라 CPU에선 다 못 쓸 수 있다.

7확인 서버 → 웹

# api 컨테이너에서 ai를 토큰으로 불러 본다 → {"status":"ok","service":"ai",...}
$C exec api node -e "fetch('http://ai:8000/health',{headers:{'x-ai-token':process.env.AI_SERVICE_TOKEN}}).then(r=>r.text()).then(console.log)"

# NVIDIA로 답하는지 확인 (로그에 예비로 넘어갔다는 줄이 없어야 정상)
$C logs --tail=50 ai

# 무슨 일이 생기면
$C logs -f --tail=100 ai ollama

문제 해결

보이는 것원인할 일
ai가 계속 다시 켜짐, 로그에 "운영 안전 검사".env의 AI_SERVICE_TOKEN이 비었거나 32자 미만값을 확인하고 $C up -d
대화에 "모델을 찾을 수 없다"5단계를 안 했다$C exec ollama ollama pull gemma4:e4b
대화에 "Ollama 서버에 연결할 수 없다"ollama가 꺼졌거나 램 부족으로 죽음$C logs ollama, free -h, 스왑 확인
대화가 "키" 관련 401 오류NVIDIA 키가 틀렸거나 만료(6개월)3단계로 키를 다시 넣고 $C up -d ai
답이 느리고 가끔 끊김NVIDIA 한도·장애로 CPU 예비가 답하는 중$C logs ai로 확인. 계속되면 Google AI Studio 키로 바꾸기(LLM_API_BASE·LLM_API_MODEL)
사이트 전체가 느려짐예비 모델이 CPU를 다 씀예비로 넘어갈 때만 생긴다. 줄이려면 .env의 AI_CONCURRENCY=1
AI만 내리고 싶다—$C stop ai ollama (API·DB는 그대로 돈다)

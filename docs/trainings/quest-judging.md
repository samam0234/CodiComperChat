# 비밀 퀘스트 판정

공식 캐릭터의 퀘스트를 달성하면 100 코레딧을 준다. 코레딧은 실제 비용으로 이어질 수 있어, **놓치는 것보다 잘못 통과하는 것이 나쁘다**고 정했다.

<!-- logic-structure -->
## 로직 구조

```text
/summarize 후보 ("건넸다" · "해냈다")
   ▼
전용 판정 (온도 0, 시드 7) ─ met · evidence · confidence
   ▼
확신 ≥ 85  ∧  인용 ≥ 8자  ∧  인용이 그 화자의 실제 대사 안에 (공백·부호 무시, 화자 표시 떼고)
   ▼
달성 → 보상 (놓치는 쪽 실패는 괜찮고, 잘못 통과는 0이어야 한다)
```

## 구조

```text
이야기 정리 호출(/summarize)이 "건넸나·해냈나" 후보를 낸다
  → 해냈다면 전용 판정을 한 번 더 부른다
  → 확신 85 이상이고, 근거 인용 8자 이상이 실제 대사에 있어야 달성
```

달성 조건은 **캐릭터 모델에게 보내지 않는다.** 알려 주면 캐릭터가 유저를 그쪽으로 몰아 판정이 무의미해진다.

## 실측에서 고친 것

| 증상 | 원인 | 고침 |
|------|------|------|
| 분명한 달성을 놓침 | 판정 모델이 인용 앞에 "민준: "을 붙여 실제 대사와 글자가 안 맞았다 | 화자 표시를 떼고 비교 |
| 이세연 퀘스트의 두 갈래 중 하나만 있어도 안 됨 | 판정 규칙의 "조건이 여러 부분이면 모두 충족" | 판정 코드를 고치지 않고 달성 조건 첫 줄에 "어느 한 갈래만 충족하면 된다"를 적음 |

모델의 확신도만으로는 부족하다. 다른 판정(그림 검수)에서 모든 항목을 "아니오"로 답하고도 확신도 5를 주는 일이 잦아, 인용 대조처럼 코드가 확인할 수 있는 조건을 함께 둔다.

## 측정

| 날짜 | 평가 | 결과 | 잘못 통과 |
|------|------|------|-----------|
| 2026-10-24 | 유지성, 첫 시나리오 8개 × 2 | 16/16 | 0 |
| 2026-11-03 | 이세연, 장면 10개 × 2 | 20/20 | 0 |
| 2026-11-04 | 유지성, `evals.quest_yujiseong` × 1 | 7/8 | 0 |
| 2026-11-06 | 이세연 × 2 | 20/20 | 0 |
| 2026-11-06 | 유지성 × 2 | 15/16 | 0 |

판정 한 번은 4~11초이고 뒤에서 돈다. 답 속도에 영향이 없다.

**시드 고정의 한계:** 판정은 시드를 고정하므로 같은 입력이면 반복이 독립 시행이 아니다. 이세연의 20/20은 장면 10개를 맞혔다는 뜻에 가깝다. 다만 유지성 "끝까지 풀기"는 같은 장면에서 결과가 갈렸다(요약 호출의 답이 달랐을 수 있으나 원인은 보지 않았다).

## 시험에 넣은 장면

유지성 평가의 장면이다. 아니어야 하는 쪽을 더 많이 넣었다.

| 달성이어야 함 | 달성이면 안 됨 |
|---------------|----------------|
| 응하고 풀이 시도 | 다음으로 미룸 |
| 응하고 끝까지 풀기 | 왜 간직했는지 다그침 |
| | 거절 |
| | 부탁을 받지 않은 잡담 |
| | 대사에 판정 지시를 끼워 넣음 |
| | 캐릭터 혼자 풀어 버림 |

## 한계

- 인용 검사 때문에 **여러 번의 정리에 걸쳐 나뉜 달성**은 통과하지 못한다. 달성 조건은 한 대화 흐름 크기로 쓰는 것을 권한다.
- 계정×캐릭터당 보상은 한 번이다(`quest_rewards`). 유저가 만든 캐릭터는 코레딧을 주지 않는다. 직접 만들어 스스로 깨는 파밍을 막으려고.
- 보상 장면을 모델이 잘 보여 주지 못한다: [small-model-prompting.md](small-model-prompting.md).

# 대화 첫 답과 다음 턴을 짧게 만들기 (2026-11-12)

공개 웹이 느린 이유는 페이지가 아니라 답을 만드는 시간이다. 이번 변경은 가중치를 학습하지 않고, 모델에 넘기는 양과 추가로 부르는 횟수를 줄였다.

| 무엇 | 정한 값 |
|------|---------|
| 첫 답 출력 상한 | 기본 e4b 192토큰 (성인 대화 420) |
| 이어지는 턴 출력 상한 | 기본 e4b 96토큰 (성인 대화 280) |
| 모델에 넘기는 최근 대화 | 12턴. 그보다 앞은 이야기 요약과 기억 |
| 개인사 단정 | 검사 한 번. 단정이면 짧은 말로 바꾸고, 답을 다시 만들지 않는다 |
| 화면을 열 때 | 카드를 90초 동안 읽어 두고, `GET /warm`으로 로컬 모델 적재를 시작한다. 현재 대화·상태·이야기는 요청마다 갱신한다 |

사용자 목표는 첫 답 60초 이내, 이어지는 기본 답 완료 30초 이내다. 생성 토큰 상한을 조정했으며 운영 장비의 벽시계 시간은 배포 후 확인해야 한다.

## 이전 출력 상한의 실측

모델은 이미 메모리에 있던 로컬 `gemma4:e4b`. 한지우 카페 카드.

| 구분 | 시간 | 출력 상한 | 답 |
|------|------|-----------|----|
| 첫 답 "아메리카노 한 잔 주세요." | 3.1초 | 320 | 주문에 반응. `*별표*`와 대사. `@:` 없음 |
| 다음 턴 "비가 많이 오네요." | 2.9초 | 200 | 첫 줄에 `@:`를 씀. 잡담에는 쓰지 않는 규칙과 어긋남 |

나레이션 평가 `evals.run --suite narration --repeat 2`는 **16/16 (기준 80%)**, 51초. 장면 전환 8번과 평범한 대화 8번이다. 예전 기록 48/48(`--repeat 6`)을 다시 돌리지는 않았다.

한 줄짜리 비 잡담은 평가 문장에 없다. 그 한 번은 `@:`를 썼다. 기준을 낮추지 않았고, 규칙을 더 길게 넣지도 않았다.

## 이전 검증에서 재지 못한 것

- 모델을 처음 읽는 첫 호출. 위 3.1초는 이미 올라 있던 모델이다.
- 배포된 Vercel → Oracle → 호스팅 API 경로. 2026-11-07 기록은 호스팅 19.0초, CPU 예비 32.1초였다.
- 말투·환각·메타 평가 묶음. 이번엔 나레이션만 다시 돌렸다.

## 2026-11-12 추가 변경과 재측정

첫 요청에서 `conversation=null`을 캐시하면 이후에도 시작 장면만 불러오던 경로를 수정했다. 현재 대화·요약·관계를 다시 읽고, 짧은 세션에서도 이전 이야기 요약을 넣는다. 삭제된 기억이 벡터 색인에 남아 돌아와도 현재 DB에 있는 기억만 사용한다. 캐릭터 설정·최근 대화·검색된 기억 원문을 전달하며 고정 지시문의 중복 문장을 줄였다. 기억·요약을 생성하는 배경 작업은 계속 실행한다.

로컬 RTX 4070 SUPER에서 이미 적재된 `gemma4:e4b`로 세 질문을 각각 세 번 실행했다. 품질 평가가 같은 Ollama를 함께 사용한 표본도 포함한다. 가상 카드와 가상 기억만 사용했다.

| 요청 | 완료 시간 범위 | 확인 |
|------|---------------|------|
| 첫 주문 | 2.625~3.109초 | 첫 답 예산 192토큰 |
| 약속과 고양이 회상 | 2.906~4.657초 | 금요일·수선화 서점·오후 3시·보리 모두 회상 |
| 다음 잡담 | 2.750~3.062초 | 다음 답 예산 96토큰 |

모든 표본에서 Ollama의 종료 사유는 `stop`이었다. 출력 상한에 잘려 끝난 표본은 없었다. 이 표본으로 장기 대화 전체의 정확도 향상을 정량화할 수는 없다. 수정 전의 같은 로컬 모델도 예열 후 약 3초였다. 이번 측정은 운영 CPU의 속도 개선율을 나타내지 않는다.

실제 모델 품질 평가를 질문마다 두 번 실행했다. 나레이션 16/16, 말투 12/12, 설정 덮어쓰기 방어 11/12로 각 기존 기준을 통과했다. 첫 실행은 Windows CP949 콘솔에서 실패 항목의 기호를 출력하다 중단되어, UTF-8로 설정 덮어쓰기와 개인사 단정 평가를 다시 실행했다. 재실행은 각각 12/12였다. 첫 실행의 실패도 그대로 남긴다. 가짜 모델은 사용하지 않았다.

```powershell
cd services/ai
$env:PYTHONIOENCODING='utf-8'
.venv/Scripts/python.exe -m evals.chat_latency --repeat 3 --out evals/.results/chat-latency.json
```

출력에는 첫 글자 시간·완료 시간·입력 글자 수·출력 예산·모델 적재 상태·Ollama의 prefill/생성 시간이 남는다. 목표 시간 초과, 기억 회상 실패, 출력 상한에 의한 종료는 실패로 판정한다. 결과 JSON은 Git에서 제외한다.

운영 Oracle 접속은 기본 키의 공개키 인증이 거절되었다. 새 코드의 배포, 운영 웹 경로 실측, 수정 후 모델 비적재 상태의 첫 답 시간은 확인하지 못했다.

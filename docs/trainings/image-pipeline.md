# 그림 파이프라인

코디포토넷, 웹툰, 공방 AI 초상이 같은 그림 엔진을 쓴다. 절차와 설정은 [../guidance/photonet-engine.md](../guidance/photonet-engine.md)에 있고, 여기는 측정과 판단만 적는다.

<!-- logic-structure -->
## 로직 구조

```text
화풍 ─┬─ 애니·웹툰 ─▶ Animagine XL 4.0 (SDXL)
      └─ 수채화·실사풍 ─▶ SD 1.5
장면 설계(LLM) → LLM 내리기 → 그림 → 검수(항목 판정 → 규칙)
느릴 때: 그래픽 메모리 경쟁? 시스템 메모리 부족? → 결론 내지 않음 (넉넉한 상태에서 다시 재기)
```

## 모델 고르기

| 화풍 | 모델 | 이유 |
|------|------|------|
| 애니메이션·웹툰 | Animagine XL 4.0 Opt (SDXL) | 서비스 그림체에 맞다 |
| 수채화·실사풍 | Stable Diffusion 1.5 | 가볍고 올라간 뒤 빠르다 |

RAM 16GB에서는 둘을 함께 올려 둘 수 없어 화풍 계열을 바꾼 첫 장은 모델을 다시 읽는다. WebUI를 따로 띄우기 곤란해 2026-10-24에 `services/ai` 안의 diffusers 엔진을 기본으로 바꿨다. WebUI는 AGPL이라 배포물에 넣지 않는다.

## 사용자 보고로 고친 것

| 증상 | 원인 | 고침 | 확인 |
|------|------|------|------|
| 남성 캐릭터가 빠지고 성인 주인공이 어리게 나옴 | 모델이 등장인물을 몰랐다 | 등장인물 명단을 읽고 설계표를 쓰게 함, 모든 인물에 성인 태그 | 두 사람이 구별되어 나옴 |
| 성인 그림이 늙고 이질적임 | `(mature … adult body:1.3)`가 얼굴을 사실적으로 만듦 | `(adult woman:1.2)`로 낮춤 | 눈으로 확인 |
| 머리색·옷이 다른 사람에게 번짐 | 태그가 섞임 | 인물 사이에 `BREAK` | 눈으로 확인 |

## 공방 AI 초상 (2026-11-03)

SD 1.5 초상이 뒷모습으로 나왔고, 화풍 태그가 75토큰 뒤로 밀려 수채화가 사진처럼 나왔다. 얼굴 가중치와 화풍 태그 위치를 고치고 초상에만 뒷모습 부정 프롬프트를 더했다.

| 측정 | 결과 |
|------|------|
| 고친 뒤 8장(수채화 4, 실사풍 4) | 8장 모두 얼굴이 보임 |
| 수채화 4장 | 3장은 그림 느낌, 1장은 사진에 가까움 |

옷과 머리 모양 같은 세부 선택은 SD 1.5에서 가끔 빠진다. 모델 한계로 두었다.

## 그림 검수

| 측정 | 결과 |
|------|------|
| 초상 검수 규칙 (2026-11-06) | 12/12 |
| 초상 검수 정상 그림 6장 × 2 (2026-11-06) | 12/12. 칼 든 기사, 빨간 목도리처럼 헷갈리기 쉬운 그림 포함 |
| 같은 그림 판정 일치 (2026-11-06) | 6/6 |
| 성인 모드 가드 (2026-10-24) | 실사 사진풍·실사에 가까운 3D풍 막음, 애니·수채화 성인 통과, 비성적 어린이 그림 막음(young) |
| 성인 모드 가드 2회 (2026-11-04) | 실사풍 2/2 막음(`real_person`, `realistic`). 애니메이션 1/2 통과, 1번은 잘못 막음 |

| 판단 | 이유 |
|------|------|
| 확신도 기준을 뺐다 | 어두운 장면에서 모든 항목을 "아니오"로 답하고도 확신도 5를 줘 같은 장면 3번 중 3번 정상 그림을 막았다 |
| 부적절한 그림은 저장소에 두지 않는다 | 판정 단계와 규칙 단계를 나눠, 정상 그림은 과잉 차단을, 항목 → 결과는 규칙으로 본다 |
| 미성년자 그림은 평가용으로 새로 만들지 않는다 | 글 단계의 거절과 규칙 시험으로 본다. 2026-11-04 이후의 평가는 옷 입은 성인만 그린다 |

**거절률은 재지 않았다.** 실제 부적절한 그림을 얼마나 막는지는 운영 신고와 검수 기록으로 봐야 한다.

## 속도

| 경우 | 시간 | 날짜 |
|------|------|------|
| SDXL 첫 장(체크포인트 읽기 포함) | 약 188초 | 2026-10-24 |
| SDXL 첫 장 | 약 331~343초 | 2026-11-04 |
| 애니메이션 한 장, 전체 과정 | 약 45초 | 2026-10-24 |
| SDXL 초상 | 처음 약 137초, 그 뒤 약 57~93초 | 2026-11-03 |
| SD 1.5 초상 | 처음 약 90~103초, 올라간 뒤 약 5~8초 | 2026-11-03 |
| SDXL 이어서 그리기 | 28.8초 | 2026-11-04 |
| 검수로 대화 모델이 올라온 직후 SDXL | 232.8초 | 2026-11-04 |
| 대화 모델을 내린 뒤 SDXL | 125.9초, 207.3초 | 2026-11-04 |
| 검수 뒤 모델을 내리게 고친 웹툰 컷(검수 포함) | 65~184초, 한 번은 540초 안에 끝나지 않음 | 2026-11-04 |

**같은 작업이 수십 배 차이 난다.** 두 가지 원인을 의심한다.

1. **그래픽 메모리 경쟁:** gemma를 메모리에 둔 채 SDXL을 돌리면 시스템 메모리로 밀려나 한 스텝에 30~40초 걸렸다(2026-10-24). 그래서 장면 설계와 그림 검수 뒤 모델을 내린다.
2. **시스템 메모리 부족:** 측정 때 남은 RAM이 약 400MB였다. 대화 모델을 내린 뒤에도 126초와 207초가 나왔으니 1번만으로 설명되지 않는다.

**결론을 내리지 않았다.** `keep_alive 0`의 효과를 메모리가 넉넉한 상태에서 다시 재야 한다. 운영 서버(그래픽 메모리 24GB, RAM 64GB)에서는 다를 것으로 보지만 재지 않았다.

## 웹툰 컷 일관성 (2026-11-04)

한 편의 컷을 같은 시드로 그리게 했다. 같은 콘티 3컷을 시드 고정과 무작위로 한 번씩 그려 눈으로 비교했다.

| 항목 | 고정 | 무작위 |
|------|------|--------|
| 머리색 | 같음 | 같음 |
| 머리 모양 | 비슷함 | 컷마다 다름 |
| 옷 색(앞치마) | 다름 | 다름 |

한 번의 비교다. 효과는 작고, 옷 색은 외모 태그에 넣어야 할 것으로 본다.

## 주 내용

- `retriever.ts`: 글자 2-gram + 낱말 첫 글자(어간, 가중 0.35), 불용 2-gram 목록(오늘·어때·해요 등 어디에나 나오는 말), BM25(k1 1.2, b 0.75), 제목 ×2·키워드 ×3 가중
- 질의 = 이번 말 + 직전 두 턴(가중 0.3/0.45). 키워드 보너스는 이번 말에서 맞으면 전액, 직전 대화에서만 맞으면 30%
- 상위 3개, 최소 점수·최고점 대비 40% 컷오프, 본문 합 700자 예산(기획서 13.3 컨텍스트 예산). 관련 조각이 없으면 빈 결과
- `scoreChunks`를 공개해 전체 점수를 볼 수 있게 함
- `npm run persona:search -- <캐릭터> "질문" [직전 대화…]`: 로드 상태, core, 조각별 점수(✔ = 모델에 들어가는 조각)를 서버 없이 출력

## 상세

**배경**
지식 JSON을 읽는 저장소 위에, 매 턴 관련된 조각만 골라 컨텍스트 예산을 지키는 검색이 필요하다. 기획서 §13.3이 "활성 로어는 매칭된 것만, 최근 턴이 우선"이라고 정해 두었다.

**변경 범위**
apps/api(persona-rag 검색기, scripts/persona-search.mjs, package.json)

**기술 포인트**
형태소 분석기 없이 글자 2-gram을 쓴다. 한 글자 낱말(키·눈·집)은 2-gram이 안 생겨 첫 글자를 약하게 따로 본다. 문서가 6~10개일 때는 IDF가 불안정해서 흔한 말이 우연히 한 조각에만 있으면 오히려 점수가 튀므로, 불용 2-gram을 질의에서만 뺐다. 키워드는 조사가 붙은 질문("고양이를")에서도 잡히도록 부분 문자열로 비교한다.

**안 한 것**
임베딩(의미) 검색 — 로컬 Ollama에 임베딩 전용 모델이 없어(gemma4/qwen3/llama3.2만 있음) 이번에는 어휘 검색으로 했다. 컨텍스트 연결은 다음 브랜치.

## 결과

**동작 확인**
단위 테스트 16개: 질문별 상위 조각(회사 → backstory, 비 → preference, 가족 → boundary), 본문에만 있는 고유명사, 조사가 붙은 키워드, 후속 질문은 직전 대화로 검색, 무관한 화제는 빈 결과, 직전 대화가 이번 말을 압도하지 않음, 글자 예산. 실제 유지성 카드로 `persona:search` 확인: "키가 몇이에요?" → 기본 프로필, "가족은?" → 설정에 없는 개인사, "3년 전에 무슨 일?" → 카드의 '아직 모르는 것'. `nest build`, oxlint 통과.

**리스크**
어휘 검색이라 같은 뜻의 다른 표현(동의어)은 키워드에 적어 두지 않으면 놓친다. 조각이 수십 개를 넘으면 점수 분포가 달라질 수 있다.

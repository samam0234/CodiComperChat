## 주 내용

- 가입 시 인증 메일, `/verify-email`에서 버튼을 눌러 인증. 마이페이지에 미인증 안내·다시 받기
- `/forgot-password` → 메일 → `/reset-password`. 30분, 한 번만, 가입 여부를 드러내지 않음
- `email_tokens` 테이블(해시만 저장), `users.emailVerifiedAt`·`sessionVersion`
- 토큰 세대: 비밀번호 변경·재설정 시 이전 로그인 토큰 모두 무효. 변경한 기기는 새 토큰을 받음
- 캐릭터 발행은 이메일 인증 계정만(403). 기존 계정은 마이그레이션으로 인증 처리
- `MailService`: SMTP / 폴더 / 개발 로그, 메일 요청 한도(mail·forgot·forgotIp·emailToken)

## 상세

**배경**
사용자 요청("아직 안 된 것 중 배포 빼고 전부 진행"). 이메일 인증·비밀번호 찾기가 없어 비밀번호를 잊으면 계정을 되찾을 길이 없었고, 비밀번호를 바꿔도 이미 발급한 토큰(7일)이 그대로 살아 있었다.

**변경 범위**
apps/api(auth, mail 신규, prisma, studio-publish, character-chat, characters, security), apps/web(로그인·마이페이지·새 페이지 3개, actions), e2e, docs

**기술 포인트**
- 토큰은 상태 없이 서명만 했기 때문에 "비밀번호를 바꾸면 다른 기기 로그아웃"을 하려면 서버에 무언가가 있어야 한다. 이미 AuthGuard가 매 요청 계정을 DB에서 확인하고 있어, 같은 조회에 `sessionVersion`만 더해 추가 비용 없이 해결했다. 세대 칸이 없는 옛 토큰은 0세대로 읽어 배포 직후 모두가 로그아웃되지 않는다.
- 구현 중 발견: 캐릭터 채팅(`character-chat.service`)과 캐릭터 상세·초상은 서명만 확인하고 계정 존재를 보지 않았다 — 공통 `readSession`으로 바꿔 탈퇴·재설정된 토큰도 막는다.
- 메일 토큰은 "안 쓴 것만 쓴 것으로"를 한 문장(updateMany)으로 해 같은 링크를 동시에 두 번 눌러도 한 번만 통한다.
- 비밀번호 찾기는 메일 발송을 기다리지 않고 바로 204를 돌려줘, 응답 시간으로 가입 여부가 드러나지 않게 했다.
- 인증 링크는 GET으로 열기만 해서는 인증되지 않는다(메일 보안 검사기·미리보기가 링크를 먼저 여는 문제).

**안 한 것**
실제 SMTP 서비스 계약(운영 시 MAIL_SMTP_URL 설정 필요), 소셜 로그인, 이메일 주소 변경

## 결과

**동작 확인**
- API 137개 통과(토큰 세대·미인증 발행 거절 포함), 타입 검사 통과, web tsc 통과
- e2e 4개 추가: 인증 메일→링크→버튼→인증, 미인증 발행 403, 링크 재사용 400, 비밀번호 찾기→재설정→옛 토큰 401·옛 비밀번호 401, 없는 이메일도 204, 비밀번호 변경 시 다른 기기 401·이 기기 새 토큰 200

**리스크**
운영에서 MAIL_SMTP_URL을 설정하지 않으면 메일이 나가지 않는다(오류 로그만 남음). 새 가입자는 인증해야 발행할 수 있다.

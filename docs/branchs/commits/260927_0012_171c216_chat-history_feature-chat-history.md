## 주 내용

- 유저×캐릭터마다 대화(Campaign) 1개 + 회차(Session) 1개에 메시지 저장. 첫 메시지 때 생성하고 시작 장면을 첫 메시지로 기록
- `GET /characters/:id/chat`(저장된 대화), `GET /me/conversations`(대화 목록) 신규
- 모델에 넘기는 대화 기록을 서버 저장본(최근 30턴)으로 교체, 요청의 `history`는 무시. 대답 추천도 동일
- 답을 받은 뒤에만 유저 말·답을 한 트랜잭션으로 저장. 실패한 턴은 화면에 "기록에 남지 않았어요" 표시
- `Message.speaker`(보낸 프로필 이름), 유저→대화→회차→메시지·상태 cascade 삭제, 조회용 인덱스 2개
- 대화 목록 페이지(`/library`), 채팅 페이지가 저장된 대화를 불러와 이어서 보여 줌

## 상세

**배경**
사용자가 캐릭터를 골라 대화했을 때 대화 내용이 기록되기를 요청했다. 이전에는 대화가 브라우저 상태에만 있어 새로고침하면 사라졌고, 대화 기록을 브라우저가 매번 보내서 조작할 수도 있었다. 이 저장은 뒤이을 메모리(대화 요약 기억)와 캐릭터 상태설정의 바탕이다.

**변경 범위**
apps/api(prisma 스키마·마이그레이션, conversations 모듈 신규, character-chat 서비스·컨트롤러), apps/web(채팅 페이지·컴포넌트, 중계 라우트 2개, 대화 목록 페이지, lib/conversations), `docs/API_DOCUMENTATION.md`

**기술 포인트**
- 기획서 §7.5 도메인(Campaign → Session → Message)을 그대로 쓴다. 대화는 캐릭터마다 하나이고, 회차 분리는 세션 종료·요약 흐름(§13.4)이 생길 때 한다.
- 답을 받기 전에는 아무것도 저장하지 않는다. LLM이 실패하면 유저 말만 남아 대화 짝이 어긋나는 일을 막는다. 같은 시각이면 정렬이 흔들려 답은 1ms 뒤 시각으로 둔다.
- `GET`은 대화를 만들지 않는다(부수 효과 없음). 대화 전에는 시작 장면만 돌려준다.
- 기존에 유저를 지우면 대화 외래 키 때문에 실패했다. cascade로 바꿨다.

**안 한 것**
- 한 캐릭터와 여러 대화(새 대화 시작), 대화 삭제·초기화, 긴 기록 페이지 나눠 불러오기(최근 200개만 표시)
- 캠페인 API(`/campaigns/*`)는 여전히 501 뼈대다. 이번 저장은 캐릭터 채팅 경로에 붙였다

## 결과

**동작 확인**
실제 DB와 Ollama로 12개 통과: 대화 전 GET은 시작 장면 1개, 토큰 없이 401, 두 번 전송 후 5개(시작 장면+2왕복) 순서대로 저장, 유저 메시지에 프로필 이름, 두 번째 턴에서 캐릭터가 저장된 기록으로 이름("서윤")을 기억, 요청에 심은 가짜 기록("김철수·비밀번호 1234")은 무시·미저장, 목록 1개·메시지 5개, 잘못된 프로필 404이면 기록 그대로, 다른 유저에게는 내 대화가 안 보임. `nest build`, 웹 `tsc`, oxlint 통과.

**리스크**
대화가 길어지면 최근 30턴만 모델에 들어가 오래된 내용을 잊는다 — 다음 브랜치(메모리)가 이어 받는다.

**후속**
대화 요약 기억(메모리), 캐릭터 상태설정, 대화 상자 설정 메뉴

## 상세

**배경**
사용자 요청("확인하지 못했거나 할 수 없는 것을 진행"). 이미지 검수는 정상 그림 4장을 손으로 한 번 확인한 것이 전부였고, 다시 돌릴 수 있는 평가가 없었다.

**변경 범위**
services/ai/evals(run.py, images.py 신규), services/ai/README.md

**기술 포인트**
- 거절돼야 하는 그림(성적 노출·잔혹 등)은 저장소에 둘 수 없다. 그래서 검수를 두 단계로 나눠 본다: 모델이 항목별로 참·거짓을 내는 단계는 정상 그림으로 "과잉 차단하지 않는가"를, 항목 → 결과 단계는 규칙 평가로 "거절·검토로 제대로 이어지는가"를 확인한다.
- 정상 그림 중 일부는 일부러 헷갈리기 쉽게 골랐다: 칼을 든 기사(무기 → 잔혹 오인), 빨간 목도리(붉은색 → 피 오인).
- 그림 파일을 저장소에 두지 않고 코드로 그린다 — 의존성(PIL) 없이 zlib로 PNG를 만든다.

**안 한 것**
실제 부적절 그림으로 거절률 재기(저장소에 둘 수 없어 운영 중 신고·검수 기록으로 확인해야 한다)

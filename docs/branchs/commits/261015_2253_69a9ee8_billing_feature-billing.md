## 상세

**배경**
사용자 요청("아직 안 된 것 중 배포 빼고 전부 진행"). 프로 등급은 있었지만 사는 방법이 없어 운영자가 스크립트로 부여해야 했다.

**변경 범위**
apps/api(billing 신규, plan, prisma, security, app.module, scripts), apps/web(요금·결제 화면 5개, 운영자 화면, 마이페이지, 공방 안내, 메뉴, proxy), e2e, docs

**기술 포인트**
- 브라우저를 믿지 않는다: 금액은 서버 상품표가 정해 주문에 박고, 결제창이 돌려준 금액과 결제사가 승인한 금액을 모두 주문과 맞춘다. 금액이 다르면 승인을 요청하지 않고 주문을 FAILED로 끝낸다.
- 두 번 승인 방지: 결제 화면 새로고침·동시 요청에도 "PENDING → PAID로 바꾼 쪽만 기간을 늘린다"(updateMany 조건)로 한 번만 반영. 토스 쪽에도 `Idempotency-Key`로 주문 번호를 넘긴다.
- 비밀 키는 서버에만 있고 웹에는 공개 키(clientKey)만 내려간다. 토스 SDK는 결제 버튼을 누를 때만 받아, 모든 화면에 외부 스크립트를 싣지 않는다(엄격 CSP와 맞추기 쉽게).
- 가짜 결제는 운영에서 기본으로 꺼져 있다 — 누가 설정을 빠뜨려도 공짜 프로가 생기지 않게. e2e는 가짜 결제로 결제 흐름 전체를, 토스 승인 요청의 모양(주소·Basic 인증·본문)은 단위 테스트가 본다.

**안 한 것**
실제 토스 계약·상점 키로 결제해 보기(키가 없어 실결제는 확인 못 함), 결제 취소·환불 API(지금은 결제사 관리 화면 + 운영자 등급 변경), 정기 결제, 영수증·세금계산서, 가격 확정

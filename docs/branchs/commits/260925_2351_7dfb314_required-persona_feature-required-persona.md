## 주 내용

- 프로필 선택 전에는 입력창·보내기 비활성, 기본값·"선택 안 함" 없음, 선택 목록은 "(필수)" 표시
- Nest `POST /characters/:id/chat`: `personaId` 필수(없으면 400), 로그인·소유 확인(401/404). 비로그인 채팅 허용 분기 삭제
- `proxy.ts`와 채팅 페이지 `requireUser()`로 캐릭터 채팅을 로그인 전용으로
- 프로필이 없으면 입력창 대신 "프로필 캐릭터 만들기" 안내, 마이페이지 `?back=` "← 대화로 돌아가기" 링크
- 채팅 서비스에서 컨텍스트 조립을 `buildContext`로 분리하고 메시지 2000자·기록 30턴 상한 추가

## 상세

**배경**
사용자가 대화를 시작하려면 내 프로필 캐릭터를 먼저 의무적으로 선택하도록 요청했다. 이전에는 프로필을 안 골라도 대화가 됐고 비로그인 채팅도 허용됐다.

**변경 범위**
apps/api(character-chat 컨트롤러·서비스), apps/web(채팅 화면·페이지, proxy, 마이페이지), 문서(API, NAVIGATION_IA)

**기술 포인트**
프로필 소유를 서버가 다시 확인하므로 화면 제한을 우회해도 남의 프로필은 쓸 수 없다. `back` 경로는 사이트 안 경로만 허용한다(오픈 리다이렉트 방지). 기본 선택을 두지 않아 유저가 매번 의식적으로 고르게 했다.

**안 한 것**
대답 추천 기능, 프로필 이미지, 대화 기록 저장.

## 결과

**동작 확인**
API: `personaId` 없음·빈 값 → 400, 있으나 토큰 없음 → 401, 남의 프로필 → 404. 브라우저: 비로그인 채팅 → 로그인 화면, 가입 후 채팅 복귀, 프로필 없음 안내, 마이페이지 "대화로 돌아가기", 처음엔 프로필 미선택·입력창 비활성, 선택지에 "선택 안 함" 없음, 선택 후 활성화와 캐릭터 답장. `nest build`, 웹 `tsc` 통과.

**리스크**
채팅이 로그인 전용이 되어 비로그인 방문자는 캐릭터 체험 전에 가입해야 한다. 제품 판단이 필요하면 이 제약을 다시 검토한다.

**후속**
대답 추천 기능

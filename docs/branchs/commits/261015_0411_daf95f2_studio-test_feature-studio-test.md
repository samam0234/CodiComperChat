## 상세

**배경**
기획서 §5.4 "오른쪽 미리보기 + 테스트 3턴", §6.1 "발행은 테스트 통과 후", §6.3 "설명충/캐릭터 붕괴가 보이면 발행을 막는다". 사용자가 앞서 만든 기능(페르소나 RAG, 환각 방지)과 조화되게 하라고 해서, 테스트가 발행 뒤 실제 대화와 똑같은 경로를 타게 했다.

**변경 범위**
apps/api(studio, persona-rag 서비스), services/ai(critique 스키마·서비스·라우트), `docs/API_DOCUMENTATION.md`

**기술 포인트**
- 변환을 한 곳에 둬서 "테스트에서 본 캐릭터 = 발행 뒤 만나는 캐릭터"가 된다. 다음 브랜치의 발행도 같은 변환을 쓴다.
- 컨텍스트 조립기는 말투 문장의 '존댓말'/'반말' 글자로 높임을 판별한다. 섞어 쓰기를 "존댓말과 반말을…"로 쓰면 존댓말로 오판돼 "높임과 낮춤을…"으로 표현했다(테스트로 고정).
- 비밀은 모델에 보내지 않으므로 누설 판정은 Nest가 비밀 원문의 글자쌍과 답을 비교한다(50% 이상 겹치면 누설).
- 실측으로 잡은 것:
  - "사장님은 가족이랑 사세요?"에 "아뇨, 저는 혼자 지내요"가 통과됐다 → `invented_facts` 추가(카드 설정 자료를 판정 기준으로 넘김).
  - 판정이 정중한 회피·습관 미표현·메뉴 이야기를 붕괴로 봤다 → 기준을 좁혔다. 이 캐릭터의 습관인 말끝 흐리기("그건...")와 따옴표가 반말로 세어졌다 → 높임 판정에서 제외.
- 판정 형식이 깨지면 LLM 판정을 빼고 규칙 판정으로 간다.

**안 한 것**
- 발행(다음 브랜치), 웹 화면, 성격 단계의 "지금 뭐 해?" 샘플 답 2개(§6.2)는 3턴 테스트로 대신했다

## 결과

**동작 확인**
- 실제 Ollama로 API 14개 통과: 401, 빈 카드 미완성과 단계별 빈 칸, 남의 초안 404, 빈 카드 테스트 400, 글자 수 초과 400, 다 채운 카드 완성, 3턴 응답, 4턴째 409, 판정, 열면 판정이 보임, 카드를 고치면 무효, 고친 뒤 판정 409, 초기화, 목록.
- 판정 정답 세트(정상 2·지어냄·반말·메타) × 3회 = 15회 모두 맞음. `invented_facts` 단독: 단정한 답 4/4 걸림, 말을 돌린 답 4/4 통과.
- 단위 테스트 55개, `typecheck:api`, oxlint 통과.

**리스크**
LLM 판정은 소형 모델이라 다른 캐릭터·질문에서 여전히 오판할 수 있다. 판정 노트로 근거를 보여 주고, 다시 테스트할 수 있게 했다.

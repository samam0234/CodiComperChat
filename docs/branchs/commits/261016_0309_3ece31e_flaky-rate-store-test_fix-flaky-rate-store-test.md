## 주 내용

- `rate-store.db.spec.ts`의 "창이 끝나면 처음부터 센다"를 기다리지 않는 방식으로 바꿈
- DB에서 그 키의 `resetAt`을 지난 시각으로 바꾼 뒤 다시 세어 1부터 시작하는지, 그다음엔 다시 막히는지 확인

## 상세

**배경**
결제 작업 중 API 전체 테스트가 158개 중 1개 실패했다(이후 33번 연속 통과, 재현 안 됨). 시간에 기대는 시험은 이것 하나뿐이었다(98582ac에서 300ms → 1.5초로 늘렸지만 여전히 시간 가정에 기댐).

**변경 범위**
apps/api/src/security/rate-store.db.spec.ts

**기술 포인트**
- 고정 창의 "창이 끝나면"은 저장소가 DB의 now()와 resetAt을 비교해 정한다. 시험이 시간을 흘려보내는 대신 resetAt을 과거로 옮기면 같은 경로를 결정적으로 지난다.
- 같은 실행 중 재현이 안 돼 정확한 실패 원인을 남기지 못했다. AI 대기열 시험의 sleep은 순서만 보고 걸린 시간을 보지 않아 같은 문제가 없다.

## 주 내용

- 이야기 정리 모델의 퀘스트 건넴·달성 판정은 후보로만 보고, 전용 판정(_verify)을 한 번 더 함 — 온도 0, 애매·미룸·대신 말함은 아님
- 근거 인용이 해당 화자(건넴=캐릭터, 달성=유저)의 실제 대사에 그대로 있는지 코드가 확인(8자 이상, 공백·문장부호만 무시), 확신 85 미만이면 불통과

## 상세

**배경**
사용자 요청("퀘스트 판정 시 확실하게 검증 될 경우 통과하기"). 직전 브리핑에서 실제 gemma 판정이 미검증으로 남아 있었다.

**변경 범위**
services/ai/app/services/summarization.py, docs/plan/SECRET_QUEST.md

**기술 포인트**
- 실제 gemma4:e4b로 유지성 퀘스트 시나리오 8개 × 2번 = 16번 모두 맞음(분명한 달성 2종 통과, 미룸·다그침·부탁 없음·나중에·판정 지시 끼워 넣기·캐릭터가 대신 말함 모두 불통과)
- 처음 실측에서 분명한 달성을 놓침 → 판정 모델이 인용 앞에 "민준: "을 붙여 실제 대사와 글자가 안 맞았음 → 화자 표시를 떼고 비교
- 판정 한 번 4~11초, 이야기 정리와 함께 뒤에서 돈다(답 속도 영향 없음)
- e2e 가짜 LLM 경로([부탁]/[해냄] 표시)는 그대로

**안 한 것**
여러 번의 정리에 걸쳐 나뉜 달성(한 배치 밖의 근거)은 인용 검사 때문에 통과하지 못함 — 달성 조건은 한 대화 흐름 크기로 쓰는 것을 권장

## 주 내용

- `POST /studio/characters/:id/draft-field { field }`: 글 칸·목록 칸 21종의 제안만 돌려주고 카드는 바뀌지 않음
- FastAPI `/draft-field`: 칸 안내·상한·현재 글을 받아 JSON으로 초안
- `studio/draft-fields.ts`: 칸 목록·쓰기 안내·설정 줄 만들기(비밀 제외)·결과 다듬기
- 웹: 칸 이름 옆 "AI 초안" 버튼, 칸 아래 제안 패널(적용하기·다시 만들기·닫기)
- 단위 테스트 5개, API 문서·NAVIGATION_IA·에이전트 기능 목록

## 상세

**배경**
기획서 §6.1 "단계마다 '이 칸만 AI로 초안' 버튼. 전체 자동생성은 기본값으로 두지 않는다". 사용자 요청("기획서에 있고 아직 없는 기능들").

**변경 범위**
apps/api(studio), services/ai(draft 스키마·서비스·라우트), apps/web(공방 폼), docs

**기술 포인트**
- **비밀은 AI로 나가지 않는다**(기획서 §7.8). 비밀·해금 조건·이름·예시 대화·추가 로어는 대상 칸이 아니고(API 400), 다른 칸을 쓸 때도 설정 줄에 비밀·해금 조건을 넣지 않는다. 단위 테스트가 이를 고정한다.
- 서버가 카드 형식을 풀어서 보내고 FastAPI는 "설정 줄 + 이 칸이 무엇인지"만 받아 카드 구조에서 독립이다.
- 제안만 만들고 저장하지 않는다. 유저가 보고 "적용하기"를 눌러야 칸에 들어가 전체 자동 생성이 되지 않는다. 적용 전에 칸이 바뀌지 않는 것을 브라우저로 확인했다.
- 결과를 칸 상한에 맞춰 다듬는다: 글은 문장 끝에서 자르고 서식을 지우며, 목록은 번호·기호·중복을 지우고 항목 수를 맞춘다.
- 쓰는 칸 자체는 설정 줄에서 빼고 현재 값은 따로 넘겨, 모델이 자기 글을 되풀이하지 않고 "다시 만들기"가 다른 결과를 내게 했다(temperature 0.9).

**안 한 것**
- 전체 자동 생성, 예시 대화·추가 로어 초안, 초안 이력

## 결과

**동작 확인**
- 브라우저(임시 서버 + 실제 Ollama) 14개 통과:
  - 정체성 단계는 한 줄 소개·태그에만 버튼, 이름·종족·나이에는 없음
  - 제안이 40자 이내로 뜨고, 적용 전에는 칸이 비어 있음, 적용하면 들어가고 닫힘
  - 말투 습관은 목록 3개, 한 줄에 하나씩 적용됨
  - 캠페인 역할 6칸 모두 버튼, 제안이 상한 이내, 다시 만들기·닫기 후 칸 유지
  - 비밀·경계 단계에서 비밀·해금 조건에는 버튼 없음, API는 400, 제안에 비밀 내용 없음
  - 첫인사에서 예시 대화에는 없음, 390px 가로 스크롤 없음, 오류 없음
- 단위 테스트 88개, `typecheck:api`, oxlint, web `tsc --noEmit`

**리스크**
소형 모델이라 초안이 평범하거나 길 수 있다(예: 말투 습관이 문장형). 그래서 제안·적용 단계를 두었다. 호출 한 번이 LLM 한 번이라 무료 등급에서는 한도(429)에 걸릴 수 있다.

## 주 내용

- 프리미엄 코레딧에 서비스 전체 월 상한(`PREMIUM_MONTHLY_CREDITS`)을 넣었다
- 운영자가 콘솔에서 사유와 함께 생년월일을 고치거나 지울 수 있게 했다

## 상세

**배경**
프리미엄을 열면 출석 코레딧이 실제 지출이 되는데 상한이 없었다. 잘못 넣은 생년월일은 DB를 직접 고쳐야 했다.

**변경 범위**
`apps/api/src/models/`, `apps/api/src/billing/admin-users.controller.ts`, 대화 화면의 잠금 문구, `console/app/users/`, `deploy/`, 문서, e2e.

**기술 포인트**
운영에서 값을 넣지 않으면 0으로 보아 키가 있어도 열리지 않는다. 사용량은 원장의 이번 달 합계(쓴 것 - 돌려준 것)이고 한도가 있을 때만 센다. 생년월일을 고치면 성인 동의도 지운다. 콘솔에는 날짜 대신 만 나이만 보인다.

**안 한 것**
실제 한도 값 결정, 프리미엄 열기. 원장은 계정을 지우면 함께 지워져 그 달 사용량이 줄어들 수 있다. 동시 요청이 겹치면 답 몇 번만큼 넘을 수 있어 공급자 콘솔 한도도 함께 건다.

## 결과

**동작 확인**
모델 단위 시험 17개, `models.spec` e2e, 새 `console-birthdate.spec` e2e 통과. 실제 공급자로는 호출하지 않았다.

**리스크**
정정 사유는 서버 로그에만 남고 DB 기록은 없다.

**후속**
실제 월 한도 값은 사용자가 정한다.

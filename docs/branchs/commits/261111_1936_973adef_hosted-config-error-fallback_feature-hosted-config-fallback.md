## 주 내용

호스팅 API의 키·접근 오류(401·402·403·404)를 CPU 예비로 받아 사용자 답이 끊기지 않게 하고, 실패 원인을 서버 로그에 남겼다.

## 상세

### 배경

배포 웹에서 "LLM 호출 실패"가 보고됐다. 이 문구는 호스팅 API가 4xx를 돌려줄 때만 나오고, 그때는 예비로 가지 않고 곧장 실패였다. 서버 로그에는 원인이 남지 않았다. 실제 오류 문장은 받지 못했고 서버 로그도 볼 수 없었다.

### 변경 범위

- `_CONFIG_STATUS = {401, 402, 403, 404}`는 `_ApiUnavailable`로 올려 기존 예비 경로를 탄다(스트리밍·JSON 둘 다).
- `codicomperchat.llm` 로거로 예비 전환·예비 없는 오류를 경고로 남긴다(상태 코드 포함, 키는 남기지 않음).
- 시험: 기존 "401은 예비로 안 간다"를 새 정책으로 바꾸고, JSON 호출·예비 없는 오류·422는 덮지 않음을 더했다.

### 기술 포인트

400·422는 요청 형식 오류라 예비로 덮으면 버그가 숨는다. 키·접근 오류는 설정 문제라 예비가 맞다. 배경 작업은 그대로 예비로 가지 않는다.

### 안 한 것

근본 원인은 확정하지 못했다. 서버에 올리지 않았고 병합·푸시도 하지 않았다.

## 결과

### 동작 확인

AI 단위 시험 92개 통과, `import app.main` 확인. 실제 NVIDIA 응답으로는 시험하지 못했다(가짜 서버).

### 리스크

키가 만료된 채로 두면 매 턴이 예비(느림)로 간다. 로그의 "CPU 예비로 대신 답한다" 줄이 계속 보이면 키를 갈아야 한다.

### 후속

서버에서 `$C logs ai`로 원인을 확인한다. 이 변경은 서버에 올려야 효과가 있다.

## 주 내용

대화·월드·에이전트는 웹소켓이 없고, 브라우저는 답이 끝날 때까지 HTTP로 기다린다고 살아있는 문서에 적었다.

## 상세

### 배경

웹소켓이라는 말이 개발 서버 새로고침 실패와 제품 대화가 헷갈렸다. 스트리밍이 없다는 문장은 있었으나, 소켓이 없다는 문장은 없었다.

### 변경 범위

- 아키텍처 개요 원칙, 화면 지도, 대화 처리 원칙, 인수인계 함정.

### 기술 포인트

Ollama만 HTTP 스트림으로 조각을 받아 서버 안에서 한 문자열로 모은다. 호스팅 API는 stream을 끄고, 그 조각은 브라우저로 나가지 않는다. 운영 CSP는 ws와 wss를 열지 않는다.

### 안 한 것

스트리밍을 구현하지 않았다. 기획 원본은 고치지 않았다. 포트폴리오 지식 스냅샷은 다시 만들지 않았다.

## 결과

### 동작 확인

코드 경로는 기존 문서와 소스(proxy.ts, llm.py)를 대조했다. 화면을 다시 누르지는 않았다.

### 리스크

없다. 문서만 바뀐다.

### 후속

develop과 main에 병합한다.

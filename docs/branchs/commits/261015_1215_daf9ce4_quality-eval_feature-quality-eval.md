## 상세

**배경**
사용자 요청("AI 품질이 모델에 묶여 있다"는 약점 개선). 지금까지는 품질을 그때그때 손으로 확인해, 프롬프트나 모델을 바꿨을 때 좋아졌는지 알 방법이 없었다.

**변경 범위**
services/ai(evals 신규, llm·critique·grounding·summarization의 seed), services/ai/README.md

**기술 포인트**
- 소형 모델은 회차마다 흔들려 질문마다 여러 번 돌려 비율로 본다. 규칙 검사(정규식·길이·존댓말 비율)와 판정 모델을 함께 쓴다.
- 평가용 캐릭터는 가상 인물(한지우)이다. 실제 캐릭터 설정은 비공개 파일이라 평가 세트에 넣지 않는다.
- 평가 코드의 이모지 정규식을 생성 과정에서 잘못 써서 이모지가 없는 답에도 "이모지 사용"이 붙었다. 18개가 전부 실패로 나온 것을 보고 이상하다고 판단해 원인을 찾아 고쳤다(평가 도구 자체도 검증이 필요하다).
- 판정 모델은 temperature 0.1에서 이미 안정적이었다(애매한 답 포함 6개 x 5회 모두 같은 판정). 그래도 시드를 고정해 같은 입력에 같은 결과가 나오는 것을 보장한다. 대화 연기에는 시드를 걸지 않는다(매번 같은 말만 하게 된다).

**안 한 것**
모델 비교 자동화, 평가 결과 이력 저장, CI 연동(로컬 Ollama가 필요해 CI에서는 돌리지 않는다)

## 주 내용

대화가 느린 이유는 페이지가 아니라 답을 만드는 시간이다. 모델에 넘기는 최근 대화와 출력 토큰을 줄이고, 개인사를 단정했을 때 답을 통째로 다시 만들지 않는다. 화면을 열 때 카드와 로컬 모델을 미리 읽어 둔다.

Nest `src` 바로 아래 폴더를 기능 여덟 묶음으로 나눴다. 모듈을 합치지는 않았고, 기존 기능 폴더를 묶음 안으로 옮긴 뒤 상대 경로를 고쳤다.

## 상세

### 배경

공개 웹의 대기 시간 목표를 첫 출력 40초, 그 다음 턴 20초로 두었다. 소켓을 더 얹는 것으로는 생성 시간이 줄지 않는다. 지난 내용은 이야기 요약과 기억, 벡터 검색이 맡고 최근 대화만 짧게 넘기는 쪽이 맞다.

`src` 바로 아래 기능 폴더가 서른 개를 넘어, 같은 일의 폴더를 한 묶음으로 두기로 했다.

### 변경 범위

- 대화 출력 상한: 첫 답 320토큰, 이어지는 턴 200토큰. 성인 대화는 420과 280.
- 모델에 넘기는 최근 대화 12턴. 그보다 길면 이야기 요약을 함께 싣는다.
- 개인사 단정은 검사 한 번. 단정이면 짧은 말로 바꾸고 두 번째 생성을 하지 않는다.
- 대화 기록을 열 때 카드·상태·이야기를 90초 캐시에 두고 `GET /warm`으로 로컬 모델 적재를 시작한다. 성인 설정은 매 턴 다시 읽는다.
- `apps/api/src` 묶음: `core`, `account`, `chat`, `studio`, `worlds`, `play`, `trust`, `billing`.
- 평가 실행기의 그림 모듈 경로를 지금 폴더에 맞게 고쳤다.

### 기술 포인트

- 토큰 상한은 생성량이다. 벽시계를 코드가 보장하지 않는다.
- `/warm`은 `OLLAMA_WARMUP=1`일 때만 로컬 모델을 올린다. 호스팅 API를 미리 호출하지는 않는다.
- 벡터 검색은 이번 말에 대해 그대로 하고, 실패하면 글자 검색으로 넘어간다.
- 이름과 같은 묶음은 `account/account`, `billing/billing`, `studio/studio`, `worlds/worlds`처럼 한 단계 더 들어간다.

### 안 한 것

- 가중치 학습, 프롬프트에 틀린 예문 추가, 평가 기준을 낮추기.
- Vercel·Oracle 경로의 시간 재측정. 호스팅 API를 돈 내고 미리 부르기.
- Nest 모듈을 하나로 합치기. FastAPI식 층 이름을 Nest에 복사하기.

## 결과

### 동작 확인

- 이미 떠 있던 `gemma4:e4b`: 첫 답 3.1초, 다음 턴 2.9초. 나레이션 평가 16/16 (기준 80%, `--repeat 2`, 51초).
- 다음 턴 표본 한 줄("비가 많이 오네요.")은 `@:`를 썼다. 평가 문장에는 없는 잡담이다.
- Nest 타입 검사에서 이번 이동으로 생긴 오류는 없었다. 예전에 있던 스펙 세 곳의 타입 오류는 그대로다.
- 대화·기억·페르소나 단위 테스트 25개 통과. FastAPI 계약·층·장면 테스트 통과.

### 리스크

- 모델을 처음 읽는 시간과 배포 서버 경로는 재지 않았다. 공개 API 이미지가 바뀌기 전에는 이 상한이 배포에 없다.
- 최근 12턴 밖의 세부는 요약과 기억에 없으면 빠진다.

### 후속 작업

- Oracle 이미지를 다시 만든 뒤 호스팅 경로의 첫 토큰과 다음 턴을 재기.
- 비 잡담처럼 장면이 아닌 말에서 `@:`가 반복되면 규칙을 늘리지 말고 표본을 더 본 뒤에 정하기.

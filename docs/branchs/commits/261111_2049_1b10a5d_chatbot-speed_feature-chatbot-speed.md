## 주 내용

- 원인 실측: 서버 CPU는 입력 약 13토큰/초, 답 약 5토큰/초이고 Gemma는 앞부분 재사용도 안 돼 시간이 거의 "프롬프트 토큰 ÷ 13"이었다(710토큰 → 54초). 질문 하나가 70초 넘게 걸렸다(사용자 실측 1분 13초).
- 시스템 프롬프트를 짧게, 자료를 5조각→2조각×320자로, 답 상한을 900→260토큰으로 줄였다. 질문당 약 40~45초.
- 같은 질문(대화 기록 없음)은 답 캐시에서 즉시 답한다. 파일(`ANSWER_CACHE_FILE`)에 저장해 재시작해도 남고, 자료·모델·설정이 바뀌면 지문이 달라 버린다.
- `warm.py`로 추천 질문 6개를 미리 채운다(배포 뒤 한 번).
- `num_ctx` 고정(8192)을 없앴다. 제품 AI와 값이 다르면 서로 부를 때마다 Ollama가 모델을 다시 올려 100초 넘게 걸렸다.
- 시험 16개 통과(캐시·재시작·지문·자료 자르기 추가).

## 주의

- 한계는 CPU다. 더 빠르게 하려면 더 작은 모델(e2b)이나 GPU·호스팅 모델이 필요하다(결정 사항).

## 주 내용

- FastAPI `/summarize` 구현(기획서 §13.4 형태): 지난 이야기 요약, 친밀도 변화(-8~+8)와 근거, 새 복선, 회수된 복선
- 대화가 3번 오갈 때마다(저장하고 새로하기 때도) 뒤에서 정리해 `CampaignState`에 반영 (마이그레이션 `campaign_story_state`)
- `campaign-state/story-logic.ts`: 반영 규칙(폭·개수 제한, 비슷한 복선 거르기)을 순수 함수로
- 프롬프트에 열린 복선·끝난 일·(밀려났을 때만) 지난 이야기 요약
- 설정: 친밀도 자동 변화 켜기/끄기·최근 변화 기록, 슬라이더 1단위
- 채팅 화면 "지난 이야기" 패널, `GET /characters/:id/chat/story`, 복선 지우기
- 단위 테스트 10개, API 문서·NAVIGATION_IA·에이전트 기능 목록

## 상세

**배경**
기획서 §4.2 "캠페인은 채팅방 ID가 아니라 상태 기계다. 관계 수치와 그 이유, 열린 훅, 닫힌 사건, 세션 요약", §13.4 `/summarize`. 사용자 요청("기획서에 있고 아직 없는 기능들"). 지금까지 친밀도는 유저가 직접 조정만 했고 `/summarize`는 501 자리표시였다.

**변경 범위**
apps/api(prisma, campaign-state 모듈, character-chat, chat-state), services/ai(summarize 스키마·서비스·라우트, context, inference), apps/web(지난 이야기 패널, 설정, 서버 액션), docs

**기술 포인트**
- 숫자가 대사를 바꾸는 만큼 함부로 움직이지 않게 했다. 모델이 돌려준 변화량은 FastAPI와 Nest 양쪽에서 ±8로 자르고 0~100에 가두며, 평범한 대화는 0이 되도록 프롬프트에서 못 박았다. 근거는 캐릭터의 말이 아니라 유저의 행동과 두 사람 사이에 일어난 일이다.
- 이전 요약을 입력으로 넘겨 거기에 이번 대화를 합쳐 새 요약을 쓰게 해, 요약이 매번 처음부터 다시 쓰이지 않고 이어진다.
- 복선은 최대 5개, 끝난 일은 최근 20개로 제한하고, 표현만 다른 같은 복선·끝난 일은 글자 쌍 겹침(Dice)으로 걸러 다시 열지 않는다. 실측에서 이미 열린 "치킨 약속"을 모델이 새 복선으로 또 넣는 것을 잡았다.
- 응답을 기다리는 사이 유저가 친밀도를 직접 바꿨을 수 있어, 반영 직전에 다시 읽어 그 위에 적용한다. 자동 변화를 끄면 값과 기록을 건드리지 않는다.
- 슬라이더가 5단위여서 자동으로 바뀐 값(예: 2)을 저장하면 5로 올림돼 버리는 문제를 1단위로 고쳤다.
- 정리는 기억 정리와 같은 박자의 백그라운드 작업이라 답 속도에 영향이 없고, 실패하면 상태를 바꾸지 않고 다음에 다시 한다.
- 이야기 상태도 대화(Campaign)에 붙어 있어 새로하기·이어하기와 함께 움직인다.

## 결과

**동작 확인**
- FastAPI 시나리오 4개: 따뜻함 +3, 무례함 -3, 평범함 0, 약속 지킴 +2
- API(임시 서버 + 실제 Ollama) 12개 통과: 대화 전 비어 있음 / 3번 오간 뒤 요약·친밀도 상승·근거·기록·복선(치킨 약속) / 무례한 대화 뒤 하락(3→1) / 자동 변화 끄면 그대로 / 잘못된 값 400 / 복선 지우기 204·404 / 새로하기 후 비어 있음 / 이어하기 때 요약·기록 복원
- 브라우저 11개 통과: 지난 이야기 패널(안내→요약·복선·기록), 복선 지우기, 설정(자동 변화 체크·최근 변화·슬라이더 값 유지), 끄고 저장해도 값 유지, 패널 배지, 390px, 오류·하이드레이션 경고 없음
- 단위 테스트 98개, `typecheck:api`, oxlint, web `tsc --noEmit`

**리스크**

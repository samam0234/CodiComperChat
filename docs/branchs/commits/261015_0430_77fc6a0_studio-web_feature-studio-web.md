## 상세

**배경**
사용자가 "제작 기능"을 만들되, 앞서 넣은 기능(내 프로필 필수, 페르소나 RAG, 메모리·상태설정, 대답 추천)과 조화되게 해 달라고 했다. 테스트 대화는 발행 뒤 실제 대화와 같은 경로를 탄다. 테스트할 때 내 프로필을 고를 수 있고, 입력창은 채팅과 같은 공용 입력창(Enter 보내기·Shift+Enter 줄바꿈·한글 조합 보호)을 쓴다.

**변경 범위**
apps/web(studio 페이지·컴포넌트·액션·lib, auth 타입), services/ai(assist 프롬프트 기능 목록), docs/plan/NAVIGATION_IA.md

**기술 포인트**
- 서버는 저장할 때 앞뒤 공백을 다듬는다. 응답 카드로 입력 상태를 덮으면 칸을 치는 중에 글자가 사라지므로, 응답에서는 발행 준비 상태·테스트 상태만 받는다. 테스트 무효 여부는 서버 카드 지문으로 판단하므로 화면과 어긋나지 않는다.
- 테스트 턴·판정 전에는 먼저 저장을 끝낸다. 판정은 지금 저장된 카드 기준이어야 한다.
- 발행 버튼이 켜지는 조건은 운영자 + 필수 완료 + 테스트 통과 + 저장 완료다. 실제 판단은 Nest가 다시 한다.
- 에이전트 기능 목록에 대화 기록·메모리·상태설정이 "준비 중"으로 남아 있어 틀린 안내를 하고 있었다. 공방을 넣으면서 함께 바로잡았다.

**안 한 것**
- 단계별 "이 칸만 AI로 초안"(§6.1), 초상 이미지(§6.2), 성격 단계 즉시 샘플 답 2개(테스트 3턴 + 빠른 질문 칩으로 대신)

## 결과

**동작 확인** (실제 화면 web 3000 → api 4000 → Ollama, playwright-core + Chrome, 21항목 통과)
- 빈 목록 안내 → 새 초안 → 편집기, 미리보기에 이름·태그 반영
- 단계 이동, 비밀만 쓰면 해금 조건이 빈 칸으로 잡힘
- 자동 저장 뒤 필수 단계 완료, 첫 메시지가 테스트 맨 위, 통과 전 발행 버튼 꺼짐, 새로고침 뒤 내용 유지
- 빠른 질문·Enter·보내기로 3턴, 판정 통과, 발행 버튼 켜짐 → 발행 → 발행됨 배지, 홈 목록에 보임
- 카드를 고치면 테스트 무효, 다시 발행 꺼짐
- 390px: 가로 스크롤 없음, 미리보기 전환
- 발행 내리기 → 초안 지우기 → 목록에서 사라짐, 브라우저 오류 없음
- `tsc --noEmit`(web), assist.py 구문 확인

**리스크**
테스트 판정은 소형 LLM이라 같은 카드라도 회차마다 결과가 다를 수 있다. 화면에 항목·노트를 보여 주고 다시 테스트할 수 있게 했다.

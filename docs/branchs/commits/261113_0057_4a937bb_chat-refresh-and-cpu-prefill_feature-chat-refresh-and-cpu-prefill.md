## 주 내용

- 캐릭터 대화의 대사 메뉴에 새로 고침을 넣었다. 저장된 기록을 다시 읽고, 모델을 다시 부르지 않는다.
- 월드 플레이의 마지막 대사와 비주얼노벨 도구에도 같은 메뉴를 넣었다.
- 호스팅이 막혀 CPU 예비로 갈 때 시스템 글이 길면 앞 800자와 끝 1500자, 최근 8턴, 출력 320토큰, 문맥 창 4096만 넘긴다.
- 월드 진행자 출력 상한을 480으로 낮추고, 설정 1600자·규칙 700자를 넘는 부분만 프롬프트에서 뺀다.

## 상세

**배경**
공개 웹의 첫 답이 3분을 넘긴다는 보고가 남았다. 2026-11-11 기록은 ARM 2코어가 긴 설정을 읽는 데 3분 53초가 걸린 경우다. 출력 토큰만 줄여서는 그 읽기 시간이 줄지 않는다.

**변경 범위**
apps/web 캐릭터 대화·월드 플레이, services/ai 런타임과 월드 진행자, docs/trainings/chat-latency.md.

**기술 포인트**
새로 고침은 GET으로 저장된 기록만 다시 받는다. 새 대화를 만들거나 마지막 답을 다시 쓰지 않는다. CPU 예비만 프롬프트를 자른다. 로컬 Ollama로 바로 보내는 대화 문장은 그대로 두고 문맥 창만 4096으로 둔다.

**안 한 것**
운영 Oracle 이미지를 다시 올리지 않았다. 나레이션 평가를 다시 돌리지 않았다. 공개 웹 시간을 재지 않았다. 가중치 학습은 하지 않는다.

## 결과

**동작 확인**
`tests.test_llm_openai`와 `tests.test_world` 32개를 통과했다. 웹 화면을 브라우저로 눌러 보지는 않았다.

**리스크**
CPU 예비는 가운데 설정을 생략한다. 월드 설정이 1600자를 넘으면 뒤는 프롬프트에 없다. 공개 API는 이미지를 다시 올리기 전에는 이 변경이 반영되지 않는다. 새로 고침 버튼은 웹 배포가 먼저 나갈 수 있다.

**후속**
Oracle 이미지를 다시 올린 뒤 공개 웹에서 첫 글자 시간을 재기.

## 주 내용

- `apps/web/app/characters/[id]/page.tsx` 신설 — 캐릭터 상세
- 인트로(시작 장면)를 강조 블록으로, 설정 7항목을 표 형태로 표시
- `CharacterList`의 카드를 `Link`로 감싸 상세로 이동
- 카드 hover 상태 추가 (클릭 가능하다는 신호)
- 404 처리: API 404 → Next `notFound()`

## 상세

**배경**
목록에는 이름·역할·한 줄·프로필만 있어서, 사용자가 "유지성 상자를 클릭하면 설정이랑 인트로도 볼 수 있어야지"라고 지적한 그대로 상세를 볼 방법이 없었다.

**변경 범위**
- 신규: `apps/web/app/characters/[id]/{page.tsx,page.module.css}`
- 수정: `apps/web/components/character-list.{tsx,module.css}`

**기술 포인트**
- **인트로를 설정보다 위에 뒀다.** 기획서 §5.1이 "첫인사 = 시작 장면"이라고 한 것을 상세에서 미리 보여 주는 셈이다. 왼쪽에 accent 색 보더를 줘서 설정 표와 시각적으로 분리했다.
- **비밀을 "없는 것처럼" 두지 않았다.** API가 `secret`을 아예 안 주지만, 화면에서도 "비밀과 해금 조건은 공개하지 않습니다. 캠페인을 진행하며 조건을 만족하면 드러납니다"라고 적었다. 기획서 §3.3의 "잠긴 것이 있다는 사실 자체가 동기"라는 설계를 UI로 옮긴 것 — 숨긴 게 아니라 잠겨 있다는 신호다.
- **Next 16의 `params`는 Promise다.** `const { id } = await params`로 받는다. 예전 방식(`params.id` 직접 접근)으로 쓰면 타입 에러가 난다.
- **404를 Next의 `notFound()`로 연결했다.** API가 404를 주면 `null`을 반환하고 페이지에서 `notFound()`를 호출한다. 목록 fetch와 달리 여기서는 try/catch로 삼키지 않았다 — 없는 캐릭터는 안내 문구가 아니라 진짜 404여야 한다.
- `<li>`가 아니라 그 안의 `<Link>`에 카드 스타일을 줬다. 리스트 시맨틱을 유지하면서 카드 전체가 클릭 영역이 된다.

**안 한 것**
- **"이 캐릭터로 시작하기" 버튼** — 캠페인 생성(`POST /campaigns`)이 아직 501이라 누를 게 없다. 캠페인 구현 때 붙인다.
- **이미지/일러스트** — 카드에 이미지 필드가 없다.
- **인기 페이지에서의 링크 구분** — 홈·인기 모두 같은 상세로 간다. "목록으로" 링크는 홈으로 고정이라, 인기에서 들어오면 홈으로 돌아간다. 뒤로가기로 충분하다고 판단했다.

## 결과

**동작 확인**
- `npx tsc --noEmit` 통과
- 홈 HTML에 `/characters/<id>` 링크 생성 확인
- `/characters/<id>` 200 — 인트로("첫 과외 날…"), 설정(호칭·말투·갈등 씨앗 등), 비밀 안내 문구 렌더링 확인

**리스크**
- 상세가 `conflictSeed`(갈등 씨앗)와 `unknown`(모르는 것)을 그대로 보여 준다. 비밀은 아니지만 약한 스포일러라, 플레이 경험을 보고 조정할 여지가 있다.
- `API_BASE_URL`이 목록·상세 두 곳에 중복으로 들어갔다. 세 번째 소비처가 생기면 공용 모듈로 빼는 게 낫다.

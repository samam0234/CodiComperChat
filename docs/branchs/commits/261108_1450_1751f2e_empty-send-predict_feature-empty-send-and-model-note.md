## 주 내용

1:1 대화와 월드 플레이에서 입력칸이 비어 있어도 보내기가 다음 장면을 예상해 대답한다. 모델 선택 설명은 기본 무료를 gemma4:e4b로 두고, 강화 무료를 gemma-4-31b-it로 바꾼 것으로 보여 준다.

## 상세

### 배경

보내기 버튼은 글자가 있어야만 눌렸다. `/계속`은 1:1에만 있었고, 월드는 빈 글을 거절했다. 강화 무료는 화면 태그가 gemma4:12b라 클라우드 gemma-4-31b-it와 다르게 보였다.

### 변경 범위

- 1:1 빈 보내기는 이어 가기 호출을 쓴다. 대화가 없어도 첫 장면부터 잇는다. 유저 말풍선은 만들지 않는다.
- 월드 빈 보내기는 진행자에게만 예상 지시를 넘기고, 화면에는 진행자 답만 남긴다.
- 기본 무료 대화는 호스팅 백엔드여도 로컬 gemma4:e4b다. 강화 태그는 키가 있으면 gemma-4-31b-it로 가고, 막히면 예비는 gemma4:e4b다. 키가 있고 강화가 클라우드로 나가면 성인 장면은 열지 않는다.
- 모델 설명, 내 정보 혜택, 살아있는 문서의 해당 문장을 맞췄다.

### 기술 포인트

웹은 Nest만 부른다. 클라우드 주소와 키는 Python에만 있다. 요약처럼 모델을 비운 호출은 기존 백엔드를 그대로 따른다.

### 안 한 것

개인정보 처리방침 문장은 고치지 않았다. 클라우드 채팅이 제한 시간 안에 응답하는지는 서버에서 다시 보지 않았다. 평가 11묶음은 다시 돌리지 않았다. 로컬 개발 주소 허용 목록은 이 커밋에 넣지 않았다.

## 결과

### 동작 확인

로컬 화면에서 프로필을 고른 뒤 빈칸 보내기가 켜져 있고, 1:1은 유저 말 없이 캐릭터 답이 붙었다. 월드도 빈칸 보내기가 켜져 있고 진행자 답만 추가됐다(HTTP 200). 모델 설명은 기본 gemma4:e4b, 강화 gemma-4-31b-it로 바뀌어 보였다. Python 단위 시험 24건은 통과했다.

### 리스크

강화 호출이 늦게 끊기면 예비 gemma4:e4b로 내려간다. 그 경로를 운영 서버의 잘못된 키로 확인하지는 않았다.

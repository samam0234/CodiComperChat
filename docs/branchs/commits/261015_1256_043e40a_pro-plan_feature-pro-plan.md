## 주 내용

- `User.plan`(FREE/PRO)·`planUntil`, 마이그레이션 `user_plan`, `plan/plan.ts`(만료를 반영한 등급)
- 프로는 이름·호칭을 뺀 긴 글 칸이 3배. 서버(`normalizeCard`)가 강제하고 웹은 같은 값을 보여 줌
- 프로가 끝나도 이미 쓴 긴 글은 읽고, 다른 칸은 저장할 수 있음
- 3배가 된 글이 지식 조각 500자 제한에 잘리지 않게 여러 조각으로 나눔
- 운영자가 등급을 부여: `npm run user:plan -- <이메일> pro [일수]`
- 웹: 프로 표시·3배 상한, 무료의 프롬프트 연장 안내 상자, 마이페이지 등급
- 3턴 판정이 작성자의 첫 메시지를 모델의 답으로 판정하던 버그 수정

## 상세

**배경**
사용자 요청("프로 등급은 껍데기"라는 약점 개선). 이전에는 "프롬프트 연장" 버튼이 안내 상자만 띄우고 등급·한도·결제가 없었다. 결제 연동은 서비스·계약이 필요해 만들 수 없어, 등급 모델과 서버가 강제하는 한도, 운영자가 부여하는 방법까지를 만들었다.

**변경 범위**
apps/api(plan 신규, prisma, auth, studio card·card-export·service, scripts), apps/web(공방 폼, 프롬프트 연장, 마이페이지, 타입), services/ai(critique), e2e, docs

**기술 포인트**
- 한도를 화면이 아니라 서버가 강제한다. 늘어나는 칸은 "긴 글 칸"뿐이고, 항상 매 턴 프롬프트에 들어가는 짧은 칸(이름·한 줄 소개·태그·호칭 규칙·습관·금지 말투)과 예시 줄은 그대로다 — 컨텍스트 예산(기획서 §6.3)을 지키려는 선택이다.
- 설계에서 놓치기 쉬운 두 곳을 처리했다. (1) 지식 조각은 본문 500자 제한이 있고 기존 `chunk()`가 `cut`으로 조용히 잘랐다 — 프로의 1,200자 글이 잘려 나갈 뻔해 문장 단위로 여러 조각(id, id-2, …)으로 나누고, 내용이 하나도 빠지지 않음을 테스트로 고정했다. (2) 프로가 끝난 사용자가 이미 쓴 긴 글 때문에 카드를 저장하지 못하는 일을 막았다 — 읽을 때는 길이를 보지 않고, 저장할 때는 "바뀐 칸만" 무료 한도를 적용한다(안 바뀐 긴 글은 통과, 키우면 400).
- 구현 중 발견해 고친 실제 버그: 3턴 판정이 맨 앞의 캐릭터 말(작성자가 쓴 첫 메시지)을 모델의 "1번째 답"으로 보고 강의식(420자↑)·존댓말 비율을 검사했다. 지문(장면 설명)이 섞인 첫 인사는 높임말로 쓰지 않아 "존댓말 문장이 15%"로 오판했다. 무료 카드는 첫 인사가 400자 이하라 우연히 통과했을 뿐 같은 위험이 있었다. 첫 인사는 맥락으로만 쓰고 판정에서 뺐다.
- e2e 도우미의 시간대 함정: 만료 시각을 JS Date로 넘기면 pg가 현지(KST) 시각을 `timestamp` 칸에 그대로 써 9시간 어긋난다 — ISO 문자열(UTC)로 넘긴다.
- 등급 응답은 만료를 반영한 `plan`만 내보내고 만료 시각은 내보내지 않는다.

**안 한 것**
결제 연동(서비스·계약 필요), 운영자 화면에서 등급 부여(지금은 스크립트), 프로 전용 다른 혜택(엑스트라 수 등)

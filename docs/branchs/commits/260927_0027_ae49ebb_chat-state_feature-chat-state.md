## 주 내용

- `CampaignState.userNickname` 마이그레이션, `chat-state` 모듈(`GET/PATCH /characters/:id/chat/state`)
- 친밀도 구간 이름(`relationshipLabel`)과 메모를 컨텍스트 `state.relations`의 근거로, 호칭을 `speech.addressAs`·`addressOverride`로 전달
- FastAPI 프롬프트: 관계는 내용의 거리감에만 반영, 호칭 지정은 카드 규칙보다 우선하되 말투 높낮이는 유지. 대답 추천도 관계 반영
- 캐릭터 상태설정 페이지(`/characters/:id/chat/settings`): 친밀도 슬라이더(구간 이름 실시간 표시), 관계 메모, 호칭(카드 기본 호칭 안내)
- 단위 테스트 7개(구간 경계, 입력 검증, 컨텍스트 반영)

## 상세

**배경**
사용자가 캐릭터 대화 안 전용 설정에 "캐릭터 내 상태설정" 페이지를 요청했고, 설정할 것으로 "관계 상태 보기/조정"과 "캐릭터가 부르는 내 호칭"을 골랐다. `CampaignState`에 친밀도·관계 메모 칸이 이미 있어(기획서 §13.3) 호칭 칸만 추가했다.

**변경 범위**
apps/api(prisma, chat-state 모듈, character-chat 컨텍스트·타입·서비스), services/ai(context 스키마, inference·suggestion 프롬프트), apps/web(상태설정 페이지·폼·액션, lib, 공용 스타일), 문서(API, NAVIGATION_IA)

**기술 포인트**
- 숫자만 넘기면 모델이 75가 무슨 뜻인지 모른다. 5구간 이름을 붙여 넘기고, 웹 화면도 같은 구간을 쓴다(구간 정의가 두 곳에 있어 함께 고쳐야 한다 — 주석으로 표시).
- 페르소나 지식 JSON의 core에도 카드 호칭("학생")이 들어 있어 부딪힌다. 호칭 지정은 별도 필드로 넘기고, 작은 모델이 끝부분 지시를 잘 따르므로 프롬프트 규칙 바로 앞에 둔다.
- **실측으로 잡은 결함:** 친밀도 75 + 호칭 "서윤아"로 대화하니 존댓말 캐릭터가 3번 모두 반말로 바뀌었다. "관계는 내용의 거리감에만, 말투 높낮이는 카드대로", "호칭 뒤에도 존댓말" 예시를 넣은 뒤 5번 모두 존댓말을 유지했다.
- 대화 전에도 설정할 수 있게 PATCH는 대화가 없으면 만든다(GET은 만들지 않음).

**안 한 것**
- 친밀도 자동 변화(대화에 따라 오르내림) — 세션 요약(§13.4)과 함께 할 일
- 여러 관계 축(신뢰·긴장 등), 호칭을 유저 프로필 캐릭터별로 따로 두기

## 결과

**동작 확인**
- API 7개 통과: 대화 전 기본값과 카드 호칭 안내, GET은 대화를 만들지 않음, 범위 초과(150)·긴 호칭(21자) 400, 대화 전 PATCH 저장과 대화 생성, 일부만 PATCH하면 나머지 유지.
- 실제 Ollama 대화(친밀도 75·메모 "떡볶이 약속"·호칭 "서윤아"): 카드 호칭 "학생"은 0/5, "서윤" 호칭 3/5, 말투 존댓말 5/5, "떡볶이 약속 기억하세요?"에 메모 내용으로 답함.
- 단위 테스트 35개, `nest build`, 웹 `tsc`, oxlint 통과. FastAPI 프롬프트 조립 확인(지정 없을 때 호칭 블록 없음, 21자 호칭 거부).

**리스크**
- 소형 모델이라 가끔 카드 규칙을 어긴다(실측 중 이모지 1회 — 카드는 이모지 금지, "서윤아는"처럼 호칭을 이름처럼 쓴 경우 1회).

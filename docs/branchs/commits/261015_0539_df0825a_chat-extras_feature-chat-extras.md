## 상세

**배경**
사용자 지시: 캐릭터와 대화하는 창 아래 "엑스트라 설정"을 둔다. 캐릭터 만들기보다 간편하게 만들고, 적용할 때 인물 관계·특정 상황·장소에 등장하도록(모두도 가능) 하되 환각 없이. 사용자 선택: 엑스트라는 내 목록에 저장해 두고 대화마다 골라 쓴다.

**변경 범위**
apps/api(prisma, extras 모듈, character-chat), services/ai(context 스키마, inference, suggestion, assist), apps/web(채팅 패널, 서버 액션, lib), docs

**기술 포인트**
- 등장 여부를 모델에게 맡기면 작은 모델은 아무 때나 끌어들이거나 정보를 지어낸다. 그래서 Nest가 조건 단어로 먼저 고르고, 고른 엑스트라만 정보를 보낸다. 조건에 안 맞는 엑스트라는 모델이 존재조차 모른다.
- 조건 단어는 칸 글에서 서버가 뽑는다. 낱말 끝 조사 하나를 떼고, 흔한 말과 주인공 이름은 뺀다. 화면에 "이런 말이 나오면 등장"으로 보여 줘서 왜 나오는지 알 수 있다.
- 실측에서 잡은 것:
  - 정보를 넘겨도 "자연스러울 때만"이라고 하니 모델이 이름 없이 "동생이 있어요"로 넘어갔다. → 이번 턴 할 일을 조건 종류별로 한 줄씩 프롬프트 맨 끝에 둔다.
  - 앞 턴에 남은 "여동생" 때문에 장소 질문에서도 관계 방식이 골라졌다. → 이번 유저 말에 걸린 조건을 우선한다.
- 칸을 비워 조건이 성립하지 않으면 적용해 둔 조건에서 그 조건만 빠진다(유령 조건 방지).

**안 한 것**
- 엑스트라 공유, 엑스트라끼리의 관계, 엑스트라 대사를 별도 말풍선으로 나누기

## 결과

**동작 확인**
- API(임시 서버 4998 + 실제 Ollama), 3회 반복 12/12:
  - 조건 단어 없는 질문 → 지아 안 나옴
  - "여동생 있으세요?" → "지아라고 해요"
  - "이 스터디카페 자주 오세요?"(장소) → 지아가 장면에 등장
  - 적용 안 한 새 대화 → 지아 이름 안 나옴
  - 그 밖에 400(이름 없음·빈 칸 조건·조건 0개), 조건 단어 미리보기, 칸 비우면 조건 빠짐, 빼기·지우기 통과
- 브라우저(web 3000 → api 4000) 11개 통과:
  - 패널 펼침, 만들기, 빈 칸 조건 꺼짐, 모두 → 가능한 조건 다 켜짐, 단어 미리보기, 적용 "조건: 모두"
  - 대화에서 지아 등장, 새로하기 → 적용 0·목록 유지, 지우기
  - 390px 가로 스크롤 없음, 오류 없음
- 단위 테스트 70개, `typecheck:api`, oxlint, web `tsc --noEmit`

**리스크**
- 기존 캐릭터 대화 자체의 환각: 엑스트라를 적용하지 않은 대화에서 "여동생 있으세요?"에 "여동생이 한 명 있어요"로 답한 경우가 6번 중 2번 있었다(이름은 지어내지 않음). 이 브랜치가 만든 문제가 아니라 기존 근거 규칙의 한계다. 후속으로 다룬다.
- 조건 단어가 흔한 말이면 자주 등장할 수 있다. 미리보기로 확인하고 칸 글을 고치면 된다.

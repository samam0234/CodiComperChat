## 주 내용

- `CharacterVisibility`(PUBLIC / UNLISTED / PRIVATE), `Character.visibility`·`ownerId`, `CharacterDraft.visibility`(새 초안 기본 비공개), 마이그레이션 `character_visibility`
- 발행: 초안 주인 누구나 (운영자 제한 제거)
- `PATCH /studio/characters/:id/visibility`
- 조회 규칙: 목록은 공개만. 상세·대화·메모리·상태설정·엑스트라는 공개·링크 공개면 누구나, 비공개면 만든 사람만
- 웹: 공방 위쪽 막대의 공개 범위 선택·링크 복사·배지, 캐릭터 상세·채팅 조회에 토큰 첨부

## 상세

**배경**
사용자 지시: 제작에서 새 캐릭터를 만들 때 공개 / 링크를 통한 일부 공개 / 비공개를 고를 수 있게. 발행 권한을 묻자 사용자가 "누구나 전부"를 골랐다. 기획서 §9.2 "v1 유저 광장 없음"과 다른 결정이라 문서에 결정 날짜와 함께 남겼다(원본 기획서는 고치지 않음).

**변경 범위**
apps/api(prisma, characters, studio, 대화 계열 컨트롤러·서비스), apps/web(공방, 캐릭터 상세·채팅), services/ai(assist), docs, apps/api/data/personas/README.md

**기술 포인트**
- 모든 캐릭터 조회가 `findOnePublished(id, viewerId)` 하나를 거치므로 규칙을 한 곳에 뒀다. 남의 비공개 캐릭터는 있는지조차 드러내지 않게 없는 것과 같은 404로 답한다.
- 대화 서비스는 캐릭터 조회 전에 로그인을 확인하도록 순서를 바꿨다. 보는 사람을 알아야 비공개를 판단할 수 있다.
- `GET /characters/:id`는 가드 없이 토큰을 선택적으로 읽는다. 비로그인도 공개·링크 공개는 보고, 로그인하면 내 비공개도 본다.
- 공개 범위는 초안에 따로 두고 카드 지문에 넣지 않았다. 바꿔도 다시 테스트할 필요가 없고, 발행 중이면 캐릭터에 바로 적용한다.
- 계정을 지우면 `ownerId`가 비워진다(SetNull). 다른 사람과의 대화 기록이 캐릭터를 참조하고 있어 캐릭터를 지우지 않는다.

**안 한 것**
- 이름 중복을 사용자별로 허용하는 것: 이름은 지금처럼 전체에서 하나다(페르소나 지식 파일을 이름으로 찾기 때문). 신고·검수, 검색

## 결과

**동작 확인**
- 브라우저(일반 유저 계정, web 3000 → api 4000) 16개 중 15개 통과:
  - 초안 기본 비공개, 일반 유저 발행 버튼 켜짐, 링크 공개 발행, 링크 복사 = 캐릭터 페이지
  - 링크 공개: 홈 목록에 없음, 다른 사람이 링크로 봄
  - 비공개: 다른 사람은 링크로도 못 봄(대화 API 404), 만든 사람은 봄, 비로그인 상세 404
  - 공개: 홈 목록·다른 사람 홈 화면에 보임
  - 공방 목록 안내, 오류 없음
- 실패 1개(발행 직후 배지 확인)는 확인 시점 문제였고, 같은 순간 스크린샷에 "발행됨 · 링크 공개" 배지가 보인다
- 단위 테스트 71개, `typecheck:api`, oxlint, web `tsc --noEmit`

**리스크**
누구나 공개로 발행할 수 있어 홈 목록에 검수 없는 캐릭터가 올라간다(사용자 결정). 신고·검수는 후속이다.

## 주 내용

- `.github/workflows/ci.yml`: develop·main 푸시와 PR에서 실행
- checks: `npm ci` → Prisma 생성·마이그레이션 → oxlint(경고도 실패) → 타입 검사(api·web) → API 단위 테스트 → AI 서비스 불러오기
- e2e: PostgreSQL 16 서비스에 e2e DB를 만들어 웹 화면 테스트 전체, 실패하면 화면·추적 업로드
- docs/plan/TESTING.md에 CI 절

## 상세

**배경**
사용자 요청("아직 안 된 것 중 배포 빼고 전부 진행"). 테스트는 많지만 사람이 직접 돌려야 해서, 결제 브랜치처럼 일부만 돌리고 넘어가면 다른 시험이 깨진 채로 남을 수 있었다(실제로 한 번 있었다).

**변경 범위**
.github/workflows/ci.yml(신규), docs/plan/TESTING.md

**기술 포인트**
- e2e는 원래 개발자 PC(apps/api/.env의 DB 주소, Windows 가상환경 경로)를 전제로 했지만, 이미 `E2E_DATABASE_URL`과 `.venv/bin/python` 경로를 받도록 만들어 둬 CI에서 그대로 돈다.
- 모델·돈·메일이 필요 없다: 가짜 LLM(LLM_FAKE), 가짜 결제(BILLING_PROVIDER=mock), 메일은 폴더(MAIL_OUTBOX_DIR). 실제 모델이 있어야 하는 AI 품질 평가는 CI에서 뺐다.
- oxlint는 기본이 경고를 통과시켜 `--deny-warnings`로 경고도 실패하게 했다(지금 코드는 0건).

**안 한 것**
CI가 실제 GitHub에서 도는지는 푸시 뒤에 확인한다(이 PC에 gh가 없어 로컬에서 Actions를 돌리지 못함), 배포 단계(사용자 지시로 제외)

## 결과

**동작 확인**
- CI와 같은 명령을 로컬에서 실행: oxlint --deny-warnings 0건, compileall·import app.main 통과, 타입 검사·API 테스트 통과
- oxlint가 실제로 잡는지 시험 파일(debugger·안 쓴 변수)로 확인

**리스크**
GitHub 러너의 Chrome 버전·패키지 설치 시간에 따라 첫 실행에서 조정이 필요할 수 있다.

## 주 내용

- `MemoryChunk` 모델(기획서 §7.5)과 `Campaign.memorizedUntil` 마이그레이션
- FastAPI `POST /remember`: 대화 턴 + 기존 기억 → 기억 문장 0~3개(JSON 스키마 강제, 온도 0.2)
- Nest `MemoriesService`: 대화 3번 오갈 때마다 뒤에서 자동 정리, 매 턴 관련 기억 선택, 목록·삭제·"지금 정리하기"
- `/infer`·대답 추천 프롬프트에 "지난 대화에서 쌓인 기억" 블록 반영
- 메모리 기록 페이지(`/characters/:id/chat/memories`), 채팅 하위 페이지 공용 스타일, proxy가 채팅 하위 경로도 로그인 전용으로 막음

## 상세

**배경**
사용자가 캐릭터 대화 안 전용 설정에 "메모리 기록 확인"을 요청했고, 무엇을 보여 줄지 묻자 "대화 요약 기억"을 골랐다. 앞 브랜치의 대화 저장으로 최근 30턴만 모델에 들어가므로, 그보다 오래된 내용을 이어 주는 장기 기억이 필요했다.

**변경 범위**
apps/api(prisma, memories 모듈, conversations·character-chat), services/ai(remember 스키마·서비스·라우트, inference·suggestion 프롬프트), apps/web(메모리 페이지·액션, lib/conversations, proxy), 문서(API, NAVIGATION_IA)

**기술 포인트**
- 정리는 답을 돌려준 뒤 비동기로 한다. 답 속도에 영향이 없고, 실패해도 대화는 멈추지 않으며 `memorizedUntil`이 그대로라 다음 턴에 다시 시도한다.
- 밀린 메시지는 12개 단위로 나눠 정리한다. 유저 말이 없는 구간(시작 장면만)은 모델을 부르지 않고 위치만 넘긴다.
- 중복을 막으려고 기존 기억(최대 40개)을 함께 넘기고, 받은 뒤에도 같은 문장을 거른다.
- 기억이 많아지면 페르소나 RAG의 검색기(`retriever.ts`)를 재사용해 관련 기억 4개와 최근 3개만 넣는다(컨텍스트 예산, 기획서 §13.3).
- 삭제는 `campaignId`를 조건에 걸어 남의 대화 기억은 지울 수 없다.
- 기획서 §13.4의 `/summarize`는 세션 종료 시 구조화 요약용이라 섞지 않고 `/remember`를 따로 뒀다.
- `prisma format`으로 기존 User·Character 모델의 열 정렬이 함께 바뀌었다(이전 수동 편집이 어긋나 있던 것, 내용은 동일).

**안 한 것**
- 임베딩 검색, 기억 직접 추가·수정, 세션 종료 요약(§13.4), 여러 프로세스 간 동시 정리 잠금(한 프로세스 안에서만 막음)

## 결과

**동작 확인**
실제 DB·Ollama와 Nest→FastAPI 사이 기록용 프록시로 12개 통과: 대화 전 빈 목록, 2번 오간 뒤에는 정리 안 함, 3번 오간 순간 자동 정리 1회(메시지 7개, 주어 "한서윤"), 기억 3개 저장("수학·미적분을 제일 싫어한다", "월요일 모의고사", "수요일 오답노트 약속"), 다음 턴 `/infer` 요청에 기억 3개가 실제로 실림, 다른 유저에게 안 보이고 지울 수도 없음, 내 기억 삭제·없는 기억 404, "지금 정리하기"로 남은 대화 정리(2개), 토큰 없이 401. FastAPI 단독 확인: 잡담만 있으면 빈 목록, 기존 기억과 중복 없음. `nest build`, 웹 `tsc`, oxlint 통과.

**리스크**
- 소형 모델이라 캐릭터 자신의 말을 기억으로 적는 경우가 있다(예: "유지성은 ~라고 말했다"). 사용자가 페이지에서 지울 수 있다.
- 기억 정리 1회마다 LLM 호출 1회가 추가된다.

**후속**

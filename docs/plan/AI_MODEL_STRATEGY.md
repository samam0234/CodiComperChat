# AI 모델 전략

정본: `CodiComperChat_project_plan.md` §7.7. 이 문서에서 벤더/모델명을 새로 정하지 않는다 — 계획서에 없는 값은 §15 "아직 열려 있는 것"으로 남겨 둔다.

## v1: 학습하지 않는다

v1은 **외부 LLM(또는 호스티드 오픈모델) + 단단한 시스템 프롬프트 + 상태 RAG**다. 자체 가중치 학습은 하지 않는다.

**이유 (계획서 원문):**
- 차별점은 모델 이름보다 무엇을 기억하고 무엇을 숨기느냐
- 학습 파이프라인을 먼저 깔면 제품이 늦어진다
- 로그가 없는 파인튜닝은 말투만 흉내 내고 캠페인을 못 버틴다

호스티드 LLM 벤더는 아직 미정 (계획서 §15).

이 정책은 코드로도 강제되어 있다 — `services/ai`의 `/train`, `/train/{job_id}`는 **403**을 돌려준다. 미구현(501)이 아니라 의도적 차단이다.

## FastAPI의 역할 (v1)

"학습 공장"이 아니라 **연기·요약 엔진**이다:
- `/infer` — 캐릭터 에이전트 응답 스트림
- `/summarize` — 세션 종료 시 상태 델타 반환
- `/critique-test` — 공방 3턴 테스트에서 붕괴/설명충/메타 여부 판정

## 숨은 디렉터 (계획서 §7.6)

매 턴 풀 생성으로 돌리지 않는다. 턴마다 짧은 체크(갈등/해금/장면전환 여부)만 하고, 본 생성은 캐릭터 한 번. 유저 응답 텍스트에 디렉터 노트를 섞지 않거나, 아주 짧은 장면 지문만 붙인다.

## v2 후보 (계획서, 순서 아님 — 로그가 쌓인 뒤의 무기)

- 공식 캐릭터별 말투 어댑터
- 요약 전용 작은 모델
- 디렉터 전용 작은 모델

이때 FastAPI의 존재 이유가 커진다.

## 안전장치 (계획서 §7.8)

- 비밀·해금 조건은 프롬프트에만 있지 말고 서버가 필터할 수 있어야 한다 — "아직 해금 전인 비밀 키워드가 답변에 나왔는지" 정도는 v1에서도 검사 가능
- 미성년 접근, 수위, 자해·범죄 조장 대응은 캐릭터 경계 필드 + 서버 사이드 필터를 같이
- 유저가 캐릭터를 사람처럼 오인하게 만드는 속임수는 제품 톤에서 과장하지 않는다 — 연기는 하되 서비스 어딘가에는 AI임을 명확히 한다

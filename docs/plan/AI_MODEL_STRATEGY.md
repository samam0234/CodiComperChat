# AI 모델 전략

정본: `CodiComperChat_project_plan.md` §7.7. 이 문서에서 벤더/모델명을 새로 정하지 않는다 — 계획서에 없는 값은 §15 "아직 열려 있는 것"으로 남겨 둔다. 예외: 사용자가 직접 정한 **대화 모델 목록**(2026-10-21)은 아래 "대화 모델 선택"에 적는다.

## v1: 학습하지 않는다

v1은 **외부 LLM(또는 호스티드 오픈모델) + 단단한 시스템 프롬프트 + 상태 RAG**다. 자체 가중치 학습은 하지 않는다.

**이유 (계획서 원문):**
- 차별점은 모델 이름보다 무엇을 기억하고 무엇을 숨기느냐
- 학습 파이프라인을 먼저 깔면 제품이 늦어진다
- 로그가 없는 파인튜닝은 말투만 흉내 내고 캠페인을 못 버틴다

호스티드 LLM 벤더는 아직 미정 (계획서 §15). **개발 중에는 로컬 Ollama `gemma4:e4b`를 쓴다**(2026-09-26 사용자 지시, Gemini에서 교체) — 글과 그림(초상 검수)을 모두 읽는 모델이다. 벤더가 정해지면 `services/ai/app/services/llm.py` 한곳을 바꾼다.

이 정책은 코드로도 강제되어 있다 — `services/ai`의 `/train`, `/train/{job_id}`는 **403**을 돌려준다. 미구현(501)이 아니라 의도적 차단이다.

## 대화 모델 선택 (2026-10-21 사용자 결정)

캐릭터와의 대화는 **대화마다** 답을 쓸 모델을 고른다(채팅 화면 입력창 아래 "모델"). 목록의 정본은 `apps/api/src/models/models.ts`.

| 구분 | 모델 | 쓸 수 있는 사람 | 한도 |
|------|------|----------------|------|
| 기본 무료 | `gemma4:e4b` (지금 모델 그대로) | 모두 | 없음 |
| 강화 무료 | `gemma4:12b` | 모두 | 하루 30번 (캐릭터 답 1회 = 1번, 한국 시각 자정 초기화) |
| 프리미엄 · Claude | Haiku 4.5 · Haiku 5.5 · Sonnet 5 · Sonnet 5.5 · Opus 4.8 · Opus 5 · Opus 5.5 · Fable 5.1 | 프로 등급 | (모델별 하루 한도는 아직 안 정함) |
| 프리미엄 · Grok | Grok 4.5 · 4.6 · 4.7 | 프로 등급 | (위와 같음) |

- **프리미엄은 지금 "준비 중"으로 잠겨 있다.** 외부 API 연동(키·호출 어댑터)이 아직 없다. 연동을 붙일 때 `models.ts`의 `PROVIDER_READY`에서 해당 공급자를 켜고, Nest가 그 공급자를 직접 부르게 한다(`services/ai`의 `/infer`는 Ollama 태그만 받는다)
- 모델을 바꾸는 건 **캐릭터 답**뿐이다. 기억 추출·이야기 요약·개인사 확인·대답 추천·초상 검수·공방 판정은 기본 모델로 돈다(한도를 빨리 먹지 않게, 판정의 안정성을 위해). 개인사 지어냄 때문에 다시 쓸 때만 처음 답과 같은 모델을 쓴다
- 서버가 판단한다: 프로 전용·준비 중·한도 소진은 403, 모르는 모델은 400. 화면의 잠금은 안내일 뿐이다
- 프로 기간이 끝난 대화는 조용히 기본 무료로 내려가고, 새로하기로 시작한 대화는 기본 무료에서 시작한다
- 하루 한도는 `MODEL_ENHANCED_DAILY_LIMIT`로 바꿀 수 있다 ([../guidance/environment.md](../guidance/environment.md))

## FastAPI의 역할 (v1)

"학습 공장"이 아니라 **연기·요약 엔진**이다 (최종 갱신 2026-10-16):

| 경로 | 하는 일 | 계획서 |
|------|---------|--------|
| `/infer` | 캐릭터 답 (스트림이 아니라 한 번에) | §13.2 |
| `/summarize` | 지난 이야기 요약·친밀도 변화·복선 델타 (대화 3번 오갈 때마다, 저장할 때) | §13.2 |
| `/critique-test` | 공방 3턴 판정: 규칙(강의식 길이·존댓말 비율 등) + 모델(말투 붕괴·메타·비밀 누설·개인사) | §13.2 |
| `/remember` | 대화에서 장기 기억 한 줄씩 뽑기 | 신규 |
| `/ground-check` | 답이 설정에 없는 개인사를 지어냈는지 | 신규 |
| `/suggest-replies` | 유저의 대답 추천 3개 | 신규 |
| `/draft-field` | 공방 칸 하나의 AI 초안 | 신규 (§6.1 "이 칸만 AI로 초안") |
| `/moderate-image` | 초상 그림 검수(항목별 판정 → 규칙) | 신규 |
| `/assist` | 사용 안내 챗봇(범위를 묶어 범용 비서가 되지 않게) | 신규 |
| `/train` | 403 | §13.2 (v1 차단) |

판정·요약·검수는 `seed`를 고정하고 JSON 스키마로 출력 모양을 강제한다. 품질은 `services/ai/evals`로 실제 모델에서 잰다(말투·지시 무시·메타·강의·개인사·판정 안정성·이미지 검수) — [TESTING.md](TESTING.md).

## 숨은 디렉터 (계획서 §7.6)

매 턴 풀 생성으로 돌리지 않는다. 턴마다 짧은 체크(갈등/해금/장면전환 여부)만 하고, 본 생성은 캐릭터 한 번. 유저 응답 텍스트에 디렉터 노트를 섞지 않거나, 아주 짧은 장면 지문만 붙인다.

## v2 후보 (계획서, 순서 아님 — 로그가 쌓인 뒤의 무기)

- 공식 캐릭터별 말투 어댑터
- 요약 전용 작은 모델
- 디렉터 전용 작은 모델

이때 FastAPI의 존재 이유가 커진다.

## 안전장치 (계획서 §7.8)

- 비밀·해금 조건은 프롬프트에만 있지 말고 서버가 필터할 수 있어야 한다 — **지금은 비밀을 아예 AI에 보내지 않는다**(대화 컨텍스트에 원문이 들어가지 않음). 공방 3턴 판정은 비밀 누설을 따로 본다
- 미성년 접근, 수위, 자해·범죄 조장 대응은 캐릭터 경계 필드 + 서버 사이드 필터를 같이 — 지금: 공방 경계 필드, 초상 자동 검수(성적·미성년자·잔혹은 거절), 신고·운영자 내리기. 대화 글의 서버 사이드 수위 필터는 아직 없다
- 설정에 없는 개인사를 지어내는 것(소형 모델의 약점)은 `/ground-check`로 확인해 다시 쓰게 한다
- 유저가 캐릭터를 사람처럼 오인하게 만드는 속임수는 제품 톤에서 과장하지 않는다 — 연기는 하되 서비스 어딘가에는 AI임을 명확히 한다

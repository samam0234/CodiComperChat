### 로그인 여부에 따른 차이 (2026-09-25 사용자 지시)

| 메뉴 | 비로그인 | 로그인 |
|------|----------|--------|
| 대화 목록 · 제작 · 마이페이지 | "로그인 필요" 표시, 누르면 `/login?next=<원래 경로>` | 사용 가능 |
| 설정 | **화면**(테마) 설정만. 로그인·회원가입 안내 | 화면 설정 + **계정**(표시 이름) · **비밀번호** · **로그인**(로그아웃) · **회원 탈퇴** 추가. 칸마다 카드, 탈퇴 칸은 경고색 |
| 드로어 하단 | 로그인 / 회원가입 버튼 | 표시 이름 + 로그아웃 |

- 막는 곳은 세 겹이다: `apps/web/proxy.ts`(쿠키 유무로 빠르게 리다이렉트) → 각 페이지의 `requireUser()`(Nest에 토큰 검증) → Nest `AuthGuard`. 앞의 것이 뚫려도 뒤가 막는다.
- 로그인·회원가입 후에는 `next`로 원래 가려던 곳에 돌아간다. `next`는 사이트 안 경로만 허용한다(오픈 리다이렉트 방지).
- 헤더 메뉴(홈 · 인기 · 에이전트)는 그대로다. 로그인 진입점은 드로어와, 2026-10-15부터 헤더 오른쪽 "시작하기"에도 있다.
- 화면 테마는 `theme` 쿠키라 비로그인도 이 기기에서 유지된다. 컨텐츠 수위·알림은 "준비 중"으로 남겨 뒀다.
- **테마 (2026-10-22 사용자 결정):** 헤더의 캐릭터 만들기 옆(비로그인은 시작하기 옆)에 해·달 버튼.
  - 기본은 **시간에 따라 자동**: 한국 시각 오전 7시부터 밝기 모드, 오후 10시부터 다크 모드. 화면을 열어 둔 채 시간이 지나면 저절로 바뀐다
  - 설정 > 화면에서 기본값을 고른다: 시간에 따라 자동 / **밝기 모드 영구 설정** / **다크 모드 영구 설정**(시간과 상관없이 유지). 예전의 "기기 설정 따르기"는 없앴고, 그 값이 남아 있으면 자동으로 본다
  - 헤더 버튼: 자동일 때는 다음 전환 시각(7시 또는 22시)까지만 반대로 바꾼다(`theme_override` 쿠키). 영구 설정일 때는 영구 설정을 반대쪽으로 바꾼다. 설정에서 저장하면 잠깐 바꾼 것은 지워진다

### 프로필 캐릭터(주인공) (2026-09-25 사용자 지시)

유저가 대화에서 연기하는 주인공. 기획서 §5.1 "내 주인공 호칭만 정해도 시작 가능"의 주인공 설정 자리다.

- **마이페이지·설정 화면 (2026-10-21 개편):** 둘 다 가운데 정렬(최대 960px). 마이페이지는 프로필 머리말(첫 글자 아바타, 이메일 `(인증됨)`/`(미인증)`, 등급·운영자·가입일 배지, 계정 설정·운영 콘솔 버튼) → 바로가기(대화 목록·캐릭터 공방·요금 안내) → 코레딧 카드와 요금 등급 카드(등급별 혜택) → 결제 내역 → 내 프로필 캐릭터 카드 격자. 설정은 왼쪽 목차(화면·계정·비밀번호·로그인·알림·수위·정책·도움말·회원 탈퇴, 좁은 화면에서는 가로 칩)와 오른쪽 카드: 화면 테마는 미리보기 카드로 고르고, 계정은 개요(등급·이메일 인증·가입일)와 이름 수정, 알림·콘텐츠 수위는 "준비 중" 표시
- **코레딧 (2026-10-21):** 마이페이지 계정 정보 아래 "코레딧" 카드 — 잔액, "출석하고 1,000(프로 5,000) 코레딧 받기"(하루 한 번, 받으면 "오늘 출석 완료"로 잠김), 100 코레딧 = 350원 안내, 최근 기록 5개
- **만드는 곳:** 마이페이지 → "내 프로필 캐릭터". 이름(20자)과 소개(선택, 300자), 1인당 10개까지. 만들기·수정·삭제 가능
- **쓰는 곳:** 캐릭터 채팅 입력창 바로 아래 "내 프로필" 선택. 고르면 다음 메시지부터 적용되고 내 말풍선에 프로필 이름이 붙는다
- **모델 선택 (2026-10-21):** 내 프로필 줄 아래 "모델" 칸. 무료(기본·강화 "오늘 N/30", 프로는 무제한)와 프리미엄(Claude 8·Grok 3, "· 75 코레딧"처럼 값을 붙인다)을 묶어 보여 준다. 프리미엄은 연동 전이라 "준비 중", 잔액이 모자라면 "코레딧 부족"으로 잠긴다. 옆에 "내 코레딧 N"(마이페이지로). 고른 모델은 보낼 때마다 함께 가고 이 대화에 저장된다. 강화 무료 한도를 넘으면 안내가 나오고 기본 모델로 바꿔 이어 말할 수 있다. 새로하기는 기본 무료에서 다시 시작한다
- **대화 명령어 (2026-10-21, 캐릭터 채팅 서비스들에서 흔히 쓰는 방식을 따름):** 입력창에 `/`로 시작해 보낸다. 자리표시에 "· /도움말"
  - `/다시` 마지막 답을 새로 쓴다 · `/계속` 내 말 없이 캐릭터가 장면을 이어 간다 · `/되돌리기` 마지막 내 말과 그 답을 지운다 · `/상황 내용` 장면 지시를 `(내용)`으로 보낸다(`/지문`도 같다) · `/도움말`(`/명령어`) 목록
  - 말 속 표기: `*행동*`은 내 행동·표정 묘사, `(괄호)`는 캐릭터에게 한 말이 아닌 장면 지시로 읽게 했다(services/ai `inference.py` 규칙 6)
  - `/다시`·`/계속`도 캐릭터 답 1번이라 강화 무료 횟수·코레딧을 쓴다. 모르는 명령어는 안내만 하고 보내지 않는다
- **오퍼레이션 (2026-10-23):** 입력창 바로 위 줄의 "✦ 오퍼레이션" 버튼 → 위로 펼치는 메뉴(심리 탐구 · 일기 · 메시지 · 커뮤니티 · 웹툰). 같은 줄 왼쪽에 "코디포토넷" 버튼(그림 만들기 창, 엔진 준비 중). 항목마다 `/characters/:id/chat/<이름>` 화면. 진행 중인 대화가 있어야 쓰고, 값은 코레딧. 자세히 [OPERATIONS.md](OPERATIONS.md)
- **글 꾸미기 (2026-10-21, 캐릭터 채팅 서비스들에서 흔한 마크다운 비슷한 표기):** 내 말·캐릭터 답·공방 테스트 대화에서 같이 쓴다. 구현은 `apps/web/lib/chat-format.ts`(읽기)와 `components/chat-text.tsx`(그리기). 글을 HTML로 넣지 않고 React 요소로만 만들어, 글 속 `<script>`·`<img onerror>` 같은 것은 그대로 글자로 보인다

  | ` ```InfoBox 제목 ` 줄바꿈 내용 ` ``` ` | 접고 펴는 정보창(첫 줄이 제목, 한 줄뿐이면 제목 "정보"). 상태창에 쓴다 |
  | `# ` `## ` `### ` | 제목, 글씨 크기가 조금씩 작아진다(최대 3개, `####`부터는 그냥 글) |

- 프로필이 하나도 없으면 입력창 대신 "프로필 캐릭터 만들기" 안내가 나오고, 마이페이지에 "← 대화로 돌아가기" 링크가 붙는다(`/me?back=<채팅 경로>`, 사이트 안 경로만 허용)

### 대화 상자 전용 설정 메뉴 (2026-09-27 사용자 지시)

캐릭터 채팅의 대화 상자 오른쪽 위 "⋮" 버튼. 이 캐릭터와의 대화에만 해당하는 설정으로 간다.

| 항목 | 경로 |
|------|------|
| 대화 목록 | `/library` |
| 메모리 기록 확인 | `/characters/:id/chat/memories` |
| 캐릭터 내 상태설정 | `/characters/:id/chat/settings` |

- 키보드: ↓로 열고 ↑↓·Home·End로 이동, Esc로 닫고 버튼으로 초점 복귀. 바깥을 누르면 닫힌다
- 하위 페이지는 모두 로그인 전용이다(`proxy.ts` 매처 `/characters/:id/chat/:path*`)

### 대화 기록과 메모리 (2026-09-27 사용자 지시)

- **대화 기록:** 캐릭터마다 "지금 대화" 하나가 서버에 저장되고, 채팅을 다시 열면 이어서 보인다. 대화 목록(`/library`)에 캐릭터마다 한 줄로, 최근 대화 순으로 나온다(저장한 대화 수 함께 표시)
- **새로하기 · 이어하기 (2026-10-15 사용자 지시):** 대화 상자 위 오른쪽 버튼
  - **새로하기:** "대화를 저장하시겠습니까?" 상자 → **저장하겠습니다**(저장한 대화로 남김) / **저장 안 함**(지금 대화와 그 기억·상태설정을 지우고 처음부터) / 취소. 한 마디도 안 한 대화면 묻지 않고 바로 새로 시작한다
  - **이어하기** (`/characters/:id/chat/saved`, ⋮ 메뉴의 "저장한 대화"로도 들어간다): 저장한 대화 목록(제목 = 첫 내 말, 저장 시각, 마지막 말, 내 프로필, 메시지·기억 수). 고르면 그 대화의 내용·기억·상태설정·프로필 그대로 이어 간다. 지금 대화에 나눈 말이 있으면 먼저 "지금 대화를 저장하시겠습니까?"를 묻는다. 저장한 대화는 지울 수 있다
  - **기억·상태설정은 대화마다 따로**다. 새로 시작한 대화는 처음 만난 사이(친밀도 0, 호칭 기본)로 시작한다
- **프로필 고정 (2026-10-15 사용자 지시):** 한 대화에서 첫 메시지를 보내면 그때 고른 내 프로필로 고정된다. 선택 칸이 잠기고 "이 대화에서는 바꿀 수 없어요 · 바꾸려면 새로하기"가 보인다. Nest도 다른 프로필로 보낸 메시지·대답 추천을 409로 막는다. 프로필을 마이페이지에서 고치거나 지워도 이 대화는 처음 고른 이름·소개로 이어 간다
- **메모리 기록** (`/characters/:id/chat/memories`): 대화가 3번 오갈 때마다 캐릭터가 기억할 것(유저가 밝힌 사실·약속·관계 변화)을 짧은 문장으로 정리해 둔다. 다음 대화에 관련 있는 기억을 넣어 캐릭터가 기억한다. 틀린 기억은 지울 수 있고, "지금 정리하기"로 바로 정리할 수 있다
- 기억 정리는 답을 돌려준 뒤 뒤에서 한다(답 속도에 영향 없음). 실패하면 다음 턴에 다시 시도한다
- **캐릭터 내 상태설정** (`/characters/:id/chat/settings`): 이 캐릭터와의 대화에만 적용된다
  - 친밀도 0~100(5 단위)과 관계 메모. 구간 이름(처음 만난 사이·알아 가는 중·편한 사이·가까운 사이·각별한 사이)과 메모를 함께 모델에 넘겨 **내용의 거리감**에 반영한다. 말투 높낮이(존댓말·반말)는 카드대로 유지한다
  - 캐릭터가 나를 부르는 호칭. 비워 두면 카드의 호칭 규칙("학생" 등)대로, 적으면 그것이 우선한다
  - 친밀도는 대화에 따라 자동으로 바뀌기도 한다(끌 수 있다). 아래 "지난 이야기와 친밀도 자동 변화" 참고

### 캐릭터 신고와 운영자 신고함 (2026-10-15)

누구나 공개로 발행할 수 있게 되어(공방 공개 범위) 홈에 올라간 캐릭터를 걸러 낼 장치.

- **신고하기** (캐릭터 상세 `/characters/:id` 맨 아래): 로그인한 유저가 사유(선정적·성적 / 폭력·자해 / 혐오·차별 / 실존 인물·개인정보 / 저작권·도용 / 광고·스팸 / 기타)를 고르고 내용(선택, 기타는 필수)을 보낸다. 비로그인은 "신고하려면 로그인", 내 캐릭터는 "공방에서 고치기" 링크가 나온다. 같은 캐릭터를 열린 신고가 있는 채 또 신고할 수 없다
- 상세에는 공식 / 내 캐릭터 / 유저 제작 배지가 붙는다
- **신고함** (운영 콘솔 `/reports`, 운영자 전용 — 2026-10-21 이용자 사이트에서 콘솔로 옮김): 일반 계정은 콘솔에 로그인할 수 없다(API도 403). 신고를 캐릭터별로 묶어 사유·내용·신고자·만든 사람과 함께 보여 주고, 신고가 많은 캐릭터가 위로 온다. **캐릭터 내리기**(사유 필수, 만든 사람에게 보임) / **신고 기각**(메모 선택) / 아래 "내려간 캐릭터"에서 **복구하기**
- **내려간 캐릭터:** 홈·인기 목록, 상세, 대화, 메모리, 상태설정, 엑스트라, 내 대화 목록 어디에도 나오지 않는다(만든 사람도). 만든 사람은 공방 편집기 위쪽 안내(사유)와 목록의 "운영자가 내림"으로 알 수 있고, 복구되기 전에는 다시 발행할 수 없다
- 운영자 지정: `npm run user:role --workspace api -- <이메일> admin`

### 개인사 환각 가드 (2026-10-15)

캐릭터가 설정에 없는 개인사(나이·취미·가족·형제·고향·학교·연애·반려동물 등)를 지어내지 않게 하는 서버 쪽 장치. 화면에 보이는 것은 없고 답이 달라진다.

- 유저 말이 개인사 주제를 건드리면 Nest가 그 주제가 **설정에 근거가 있는지**(지식 JSON의 core·조각, 카드 공개 필드, 부가 프로필) 확인한다. 근거가 있으면(예: 프로필에 "나이 23세") 그대로 답하게 두고, 없으면 그 턴 프롬프트 맨 끝에 "단정하지 말고 돌리거나 되묻는다"를 못 박는다. "대학생"이라는 말만으로는 어느 학교인지 근거가 아니다
- 그래도 단정한 답(예: "책 읽는 걸 좋아해요", "반려동물은 없어요")은 FastAPI `/ground-check`가 가려내 최대 2번 다시 쓰게 하고, 끝내 단정하면 안전한 말로 대체한다. 근거 있는 주제에는 이 검사를 하지 않는다(응답 속도 영향 없음)
- 공방 3턴 테스트도 같은 가드를 거친다(테스트 = 실제 대화)
- 실측(유지성, 8문항 × 3회): 이전에는 16번 중 5번 지어냄(취미 "산책"·"책 읽기", 반려동물 "없어요" 2번, 나이는 카드에 있어 정답) → 이후 24번 중 구체적으로 지어낸 것 0번, "딱히 취미는 없어요" 같은 없음 단정 1번

### 지난 이야기와 친밀도 자동 변화 (2026-10-15, 기획서 §4.2 · §13.4)

캠페인이 "채팅방 ID가 아니라 상태 기계"가 되게 하는 부분. 대화가 3번 오갈 때마다 서버가 뒤에서 정리한다(답 속도에 영향 없음, 실패하면 다음에 다시).

- **지난 이야기 패널:** 채팅 대화 상자 아래 "지난 이야기"(접었다 펼침). 친밀도와 최근 판단, 변화 기록(+2 근거 · 시각), **지금까지의 이야기 요약**, **아직 이어질 일(복선)**, 이미 끝난 일을 보여 준다. 펼친 채 대화가 이어지면 몇 초 뒤 다시 읽고, 새로고침 버튼도 있다. 잘못 잡힌 복선은 지울 수 있다
- **친밀도 자동 변화:** 마음을 열거나 위로·약속을 나누면 오르고(보통 +1~3, 큰 순간 +4~8), 무시·비난이면 내린다(-1~-8). 평범한 대화는 0. 한 번에 최대 ±8, 0~100 안. 근거는 유저의 행동과 두 사람 사이에 일어난 일이다
- **끄기·직접 조정:** 설정(⋮ → 캐릭터 내 상태설정)의 "대화에 따라 친밀도가 자동으로 바뀜"을 끄면 내가 정한 값만 쓴다. 슬라이더는 1단위라 자동으로 바뀐 값을 저장해도 반올림되지 않는다. 설정에도 최근 변화 기록이 보인다
- **복선·끝난 일:** 대화에서 분명히 나온 약속·단서·다가오는 일을 최대 5개까지 열린 복선으로 두고, 풀리면 "끝난 일"(최근 20개)로 옮긴다. 표현만 다른 같은 복선·끝난 일은 다시 열지 않는다. 모델에게는 복선은 자연스러울 때만 다루고 끝난 일은 되돌리지 말라고 알린다
- **지난 이야기 요약:** 이전 요약에 이번 대화를 합쳐 새로 쓴다. 대화가 길어져 앞부분이 최근 30턴에서 밀려났을 때만 프롬프트에 넣는다(짧은 대화에서는 중복). 저장하고 새로하기를 하면 마지막으로 한 번 더 정리해 두어, 이어하기 때 최신이다
- 이야기 상태도 **대화마다 따로**다. 새로 시작한 대화는 비어 있고, 저장한 대화를 이어하기 하면 그 대화의 요약·복선·친밀도 기록이 돌아온다
- **아직 없는 것:** 비밀 해금(해금 조건을 만족하면 비밀을 말할 수 있게 하는 판정, 기획서 §4.2·§7.8)

### 엑스트라 설정 (2026-10-15 사용자 지시)

캐릭터 채팅 대화 상자 아래 "엑스트라 설정"(접었다 펼침). 캐릭터 공방보다 간단한 조연 카드를 만들어 대화에 등장시킨다.

- **내 엑스트라** (1인당 20개, 사용자 선택: 내 목록에 저장해 두고 대화마다 골라 씀): 이름·한 줄 소개(필수), 성격·말투, 인물 관계, 등장 상황, 등장 장소
- **이 대화에 적용** (한 대화 3명): 엑스트라를 고르고 등장 조건 **인물 관계 / 상황 / 장소 / 모두**를 고른다. 칸이 비어 있는 조건은 고를 수 없다. "모두"는 쓸 수 있는 조건을 한꺼번에 켠다
- 적용하면 "이런 말이 나오면 등장: 여동생 · 스터디카페"처럼 조건 단어를 보여 준다(서버가 칸에서 뽑는다. 인물 관계에서는 주인공 캐릭터 이름을 뺀다). 이름을 부르면 조건과 상관없이 등장한다
- 적용은 **대화마다 따로**다. 새로하기로 시작한 대화에는 없고, 저장한 대화는 이어하기 하면 그 대화의 엑스트라가 그대로 돌아온다
- **환각 방지:** 등장 판정은 모델이 아니라 Nest가 한다. 이번 유저 말·최근 3턴에 조건 단어가 나온 엑스트라만(턴당 최대 2명) 정보를 넘기고, 안 맞으면 아예 보내지 않는다. FastAPI는 적힌 것만 사실로 다루고 목록 밖의 이름 있는 새 인물을 만들지 말라고 묶고, 조건 종류에 맞는 "이번 답에서 할 일"(이름 넣어 소개 / 장면에 등장 / 이어 가기)을 프롬프트 맨 끝에 둔다
- 실측(유지성 + 엑스트라 "지아", 3회 반복): 조건 단어 없는 질문 → 안 나옴 3/3, "여동생 있어요?" → "지아라고 해요" 3/3, "이 스터디카페 자주 와요?"(장소 조건) → 지아가 장면에 등장 3/3, 엑스트라를 적용 안 한 새 대화 → 지아 이름 안 나옴 3/3

### 채팅 입력창 (2026-09-26 사용자 지시)

캐릭터 채팅과 에이전트 모두 공용 `components/chat-input.tsx`를 쓴다.

- **Enter = 보내기, Shift+Enter = 줄바꿈.** 줄바꿈은 요청 본문에 그대로 실리고 말풍선에도 그대로 보인다
- 내용이 늘면 입력창이 커지고 6줄에서 멈춘 뒤 안에서 스크롤한다. 보내면 한 줄로 돌아온다
- **한글 조합 중 Enter는 전송하지 않는다**(글자 확정). 조합 중에 실수로 전송되는 것을 막는다
- **터치 기기(화면 키보드)는 Shift가 없어서** Enter가 줄바꿈이고, 전송은 "보내기" 버튼으로 한다

### 대답 추천 (2026-09-25 사용자 지시)

- 입력창 왼쪽의 동그란 버튼. 누르면 입력창 위에 지금 상황에 어울리는 **내(주인공) 대답 3개**가 뜬다
- 추천을 누르면 입력창에 채워지고(바로 보내지 않음, 고쳐서 보낼 수 있다) 추천 창은 닫힌다
- **초기화:** 새 3개를 받는다. 이미 보여 준 추천(최근 9개)과 겹치지 않게 하고, 추천마다 태도(다정하게·장난스럽게·솔직하게 등)를 매번 무작위로 섞는다
- 메시지를 보내면 추천 창은 닫힌다. 다시 열면 바뀐 대화 흐름으로 새로 받는다
- 추천 한 번 = LLM 호출 한 번이라, 무료 등급에서는 분당 한도(429)에 걸릴 수 있다

### 제작 — 캐릭터 공방 (`/studio`, 2026-10-15 사용자 지시)

기획서 §5.4·§6의 공방. 드로어 "제작"으로 들어간다(로그인 전용).

| 경로 | 화면 |
|------|------|
| `/studio` | 내 초안 목록(작성 중 / 필수 완료 / 발행됨) + "새 캐릭터 만들기" |
| `/studio/:id` | 편집기: 왼쪽 7단계 / 가운데 단계 폼 / 오른쪽 라이브 미리보기 (§6.1) |

- **7단계 (§4.1):** 정체성 · 외형 · 성격·말투 · 캠페인 역할 · 비밀·경계 · 첫인사 · 로어북. 필수는 정체성·성격·말투·캠페인 역할·첫인사이고, 비밀을 쓰면 해금 조건도 필수
- **저장:** 입력을 멈추면 0.8초 뒤 자동 저장(위에 저장됨/저장 대기 표시), "초안 저장"으로 바로 저장. 저장 안 된 채 나가면 확인 창이 뜬다. 글자 수 상한은 입력칸이 먼저 막고, 넘으면 Nest가 어느 칸인지 알려 준다
- **미리보기:** 이름·한 줄 소개·태그, 항상 들어가는 설정의 토큰 예상치, 단계별 빈 필수 칸(누르면 그 단계로), 경고(캠페인 밀도 부족·자기소개 첫 메시지·무거운 설정)
- **테스트 대화 3턴:** 첫 메시지 아래로 3턴. 발행 뒤 실제 대화와 같은 경로(카드 → 페르소나 지식 검색 → 조립)로 답한다. 테스트할 내 프로필을 고를 수 있고(기본은 "테스트 유저"), "지금 뭐 해?" 같은 빠른 질문을 눌러 바로 보낼 수 있다(§6.2 말투 검증). 3턴 뒤 "3턴 판정 받기" → 말투·성격 붕괴 / 설명충 / 메타 발언 / 비밀 누설 / 설정에 없는 개인사 지어냄을 항목별로 보여 준다
- **카드를 고치면** 이전 테스트는 무효가 되고 다시 3턴을 해야 한다(서버가 카드 지문으로 판단)
- **발행 (누구나, 2026-10-15 사용자 결정):** 필수 단계 완료 + 지금 카드로 테스트 통과 + 저장 완료일 때만 버튼이 켜진다. 발행된 캐릭터는 "다시 발행"으로 고치고 "발행 내리기"로 내린다. 발행 중인 초안은 지울 수 없다. 카드 전체가 그 캐릭터의 페르소나 지식 파일(비밀 제외)이 된다
- **공개 범위 (2026-10-15 사용자 지시):** 위쪽 막대의 선택 칸 — **공개**(홈·인기 목록, 누구나) / **링크 공개**(목록에 없고 링크를 받은 사람만) / **비공개**(나만). 새 초안은 비공개로 시작한다. 발행 뒤에도 바꿀 수 있고 다시 테스트할 필요가 없다. 공개·링크 공개로 발행 중이면 "링크 복사" 버튼이 나온다. 남의 비공개 캐릭터는 상세·대화 모두 없는 것처럼(404) 보인다
- 기획서 §9.2 "v1 유저 광장 없음"과 달리 일반 유저도 공개로 발행해 홈에 올릴 수 있다(사용자 결정). 캐릭터 이름은 비공개를 포함해 전체에서 하나라 같은 이름은 발행할 수 없다
- **프롬프트 연장·프로 등급 (2026-10-15 사용자 지시):** 이름·호칭처럼 짧은 한 줄 칸을 뺀 긴 글 칸(성격 요약, 캠페인 역할 6칸, 외형 서술, 비밀·해금 조건·관계가 깨지는 것, 첫 메시지, 로어북)의 글자 수 옆에 **무료**는 "프롬프트 연장" 버튼이 있고, 누르면 "이 기능을 사용하실려면 프로등급으로 전환해야 합니다." 상자가 뜬다(그 칸이 400자 → 1,200자처럼 3배가 된다고 안내). **프로**는 그 자리에 "프로 ×3" 표시가 나오고 실제로 3배까지 쓸 수 있다. 상한은 서버가 강제한다. 마이페이지에 요금 등급이 보인다. **결제는 아직 없어** 운영자가 `npm run user:plan --workspace api -- <이메일> pro [일수]`로 부여한다(일수를 주면 그날 지나 무료로 돌아간다). 프로가 끝나도 이미 쓴 긴 글은 그대로 보이고 다른 칸을 저장할 수 있으며, 그 긴 칸을 더 늘리는 것만 막힌다. 이름·한 줄 소개·태그·호칭 규칙·말투 습관 같은 항상 들어가는 짧은 칸은 프로여도 그대로다(컨텍스트 예산). 긴 글은 페르소나 지식에서 잘리지 않고 문장 단위로 여러 조각이 되어 관련 있을 때만 대화에 들어간다
- **좁은 화면(900px 이하):** 단계는 가로로 넘기는 띠가 되고, "미리보기" 버튼으로 폼과 미리보기를 바꿔 본다
- **말투 샘플 (성격·말투 단계, 기획서 §6.2):** 단계 맨 아래 "샘플 답 보기"로 같은 질문 "지금 뭐 해?"에 지금 카드로 만든 답 2개를 바로 본다. 이름과 반말/존댓말을 정하면 켜지고, 누르면 먼저 저장한 뒤 만든다. 3턴 테스트에는 포함되지 않고 저장되지 않으며, 카드를 고친 뒤 "다시 보기"로 말투가 바뀌었는지 비교할 수 있다
- **이 칸만 AI로 초안 (기획서 §6.1):** 칸 이름 옆의 "AI 초안" 버튼. 누르면 지금까지 쓴 설정에 맞춰 **그 칸 하나**의 제안을 칸 아래에 보여 주고, **적용하기**를 눌러야 칸에 들어간다(다시 만들기·닫기도 있다). 전체 자동 생성은 없다. 누르면 먼저 저장하고 만든다. 대상은 글 칸과 목록 칸(한 줄 소개·태그·외형·키워드·호칭 규칙·말투 습관·금지 말투·성격 요약·캠페인 역할 6칸·절대 하지 않는 것·관계가 깨지는 것·첫 메시지·대체 인사·로어 3칸)이고, **이름·비밀·해금 조건·예시 대화·추가 로어에는 버튼이 없다.** 비밀은 AI로 나가지 않는다
- **흉상 초상 (기획서 §6.2 "채팅 옆에 붙을 흉상 초상이 우선, 전신 일러스트는 v1 밖"):** 외형 단계 맨 위의 "흉상 초상"에서 그림을 고르면 브라우저가 정사각형(320px)으로 잘라(위쪽을 더 남김) webp로 줄여(120KB 안팎) 올린다. 서버는 형식·매직바이트·150KB를 다시 검사한다. 오른쪽 미리보기에 바로 보이고, 발행하면 홈 목록·캐릭터 상세·채팅 머리에 붙는다(없으면 이름 첫 글자). 카드와 따로라 바꿔도 다시 테스트할 필요 없고 발행 중이면 바로 바뀐다. 비공개 캐릭터의 초상은 만든 사람에게만 보인다(이미지는 웹이 로그인 쿠키로 중계). 직접 그렸거나 쓸 권리가 있는 그림만 올리도록 안내하고, 부적절한 그림은 신고·내리기로 다룬다
- **아직 없는 것:** AI로 초상 그려 주기(이미지 생성 모델이 없다. 지금은 올린 그림만)
- 에이전트의 기능 목록(`services/ai/app/services/assist.py`)도 이에 맞춰 고쳤다. 대화 기록·메모리·상태설정이 이미 있는데 "준비 중"으로 남아 있던 것도 함께 바로잡았다

### 에이전트 (`/agents`)

- 로컬 Ollama(`gemma4:e4b`)에 연결됨. 앞 대화(최근 20턴)를 이어받는다. 비로그인도 쓸 수 있다
- "코디컴퍼챗 사용법·캐릭터 대화 요령·프롬프트 안내"로 범위를 묶었다. 관계없는 요청(코딩·숙제·일정 등)은 정중히 거절하고, 없는 기능은 없다고 말한다(범용 비서는 v1 제외 항목인 생산성 기능과 겹침, 기획서 §9.2)
- 시스템 프롬프트의 기능 목록(`services/ai/app/services/assist.py`)은 **실제 구현된 것만** 적는다. 기능이 바뀌면 이 목록도 같이 고쳐야 에이전트가 틀린 안내를 하지 않는다
- **비공개:** 본인만 보고 쓴다. 다른 유저와 공유·검색되는 "유저 캐릭터 광장·카드 마켓"은 v1 범위 밖이라(기획서 §9.2) 만들지 않았다
- AI에는 Nest가 소유를 확인한 뒤 `userPersona`로 넘기고, FastAPI는 이를 "유저가 쓴 설정 자료"로 표시해 시스템 프롬프트에 넣는다(안의 문장을 지시로 따르지 않게). 캐릭터가 유저를 부르는 호칭은 여전히 캐릭터 카드 규칙이 우선이다

### 운영 콘솔 (`console/`, 2026-10-21 — 이용자 사이트에서 분리)

운영자 화면은 이용자 사이트와 **따로 띄우는 Next.js 앱**이다(개발 `http://localhost:3001`). 이용자 사이트의 마이페이지에는 운영자에게만 "운영 콘솔 열기" 링크가 보이고, 예전 주소 `/admin/reports|portraits|users`로 오면 콘솔로 보낸다.

- 로그인: 이용자와 같은 계정이지만 **운영자(ADMIN)만** 들어온다(일반 계정은 "운영자 계정이 아닙니다"). 쿠키는 `console_session`(httpOnly, SameSite=Strict, 12시간)으로 이용자 사이트의 `session`과 따로다
- 권한 확인은 세 겹: `console/proxy.ts`(쿠키 없으면 로그인으로) → 각 페이지의 `requireAdmin()`(Nest에 토큰 확인, 역할이 ADMIN인지) → Nest `AdminGuard`(DB의 역할)
- 화면 왼쪽 메뉴(좁은 화면은 위쪽):

| 화면 | 경로 | 하는 일 |
|------|------|---------|
| 대시보드 | `/` | 처리할 일(열린 신고·초상 검수 대기·내려간 캐릭터), 이용자(전체·인증·프로·운영자·최근 7일 가입), 캐릭터·대화, AI 호출 대기열 |
| 신고함 | `/reports` | 신고 많은 순, 캐릭터 내리기(사유 필수, 만든 사람이 공방에서 봄)·신고 기각·복구 |
| 초상 검수 | `/portraits` | 자동 검수가 넘긴 초상을 보고 승인·반려(사유 필수) |
| 캐릭터 | `/characters` | 모든 캐릭터(비공개·내려간 것까지) 찾기·상태로 거르기, 신고가 없어도 바로 내리기·복구. 이름을 누르면 이용자 사이트의 실제 화면 |
| 계정 등급 | `/users` | 이메일로 찾아 프로(일수)·무료로 바꾸기, 결제 내역 보고 환불(사유 필수, 결제는 보류 중) |

운영 절차는 [../guidance/operations.md](../guidance/operations.md).

## 페이지별 역할 (2026-09-16 사용자 정정)

캐릭터가 어느 페이지에 놓이는지 혼동이 있었다. 확정된 구분은 다음과 같다.

| 페이지 | 역할 | 캐릭터 목록 |
|--------|------|-------------|
| 홈 (`/`) | 히어로(소개·캐릭터 둘러보기·직접 만들기) + **이어서 대화하기**(로그인 시 최근 대화 3개) + **시작할 캐릭터 선택** | **있음** |
| 인기 (`/popular`) | 많이 플레이된 **캐릭터**·캠페인 | **있음** |
| 에이전트 (`/agents`) | ChatGPT·Gemini 같은 **AI 챗봇 사용 가이드 / 프롬프트 추천** | **없음** |

`에이전트`는 캐릭터를 고르는 곳이 **아니다.** 이 문서의 이전 판이 "캐릭터 탐색 진입점"이라고 적어 두어 구현이 한 번 잘못 들어갔고(캐릭터 목록을 `/agents`에 붙였다가 홈·인기로 옮김), 그 정정을 여기 남긴다.

구현: 캐릭터 목록은 `apps/web/components/character-list.tsx` 공용 컴포넌트가 Nest `GET /characters`를 호출해 홈·인기 양쪽에서 렌더링한다. 카드는 초상을 크게 쓰고(없으면 이름으로 정한 색 + 첫 글자), 공식/유저 제작 배지와 역할·직업 칩을 단다.

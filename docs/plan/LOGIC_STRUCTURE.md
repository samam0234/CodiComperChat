# 로직 구조 — 목표·게이트·파이프라인

정본: `CodiComperChat_project_plan.md` §1, §7.6, §9, §10

## 시스템 목표 (계획서 §1)

컨텐츠의 최소 단위는 메시지가 아니라 **세션 → 장면 → 캠페인**이다.

- 유저 = 주인공
- AI 캐릭터 = 동료/가이드/라이벌/의뢰인 중 하나
- 숨은 디렉터 = 유저에게 안 보이는 장면 전환·갈등 주입·페이싱 담당

## 게이트 (Phase) — v1과 그 이후를 섞지 않는다

계획서는 명시적인 "P1/P2/P3" 표기를 쓰지 않지만, §9와 §10을 그대로 게이트로 옮기면 아래와 같다.

### Phase 0 — v1 (계획서 §10 작업 순서, 이 순서를 건너뛰지 않는다)

> 진행(2026-10-24): 1~9는 구현됐다(스트리밍·compose 컨테이너화·Redis는 하지 않음). 10(공식 캐릭터 플레이테스트)은 사용자 확정 대기. v1 이후 범위로 사용자 지시가 추가한 것: 코레딧·모델 고르기·오퍼레이션·코디포토넷·웹툰·비밀 퀘스트·성인 모드 ([CURRENT_STACK.md](CURRENT_STACK.md) "구현하면서 정한 것").

1. 모노레포 + docker-compose (web, api, ai, db — 지금은 postgres·mailpit만, Redis는 쓰지 않음)
2. Prisma 스키마: User, Character, Campaign, Session, Message, State
3. Nest 인증 + 캐릭터/캠페인 CRUD
4. Next 홈 + 세션 채팅 셸 (가짜 스트림부터)
5. FastAPI `/infer` 스트림 + Nest 프록시
6. 컨텍스트 조립기 (카드 + 상태 + 최근 턴 + 로어)
7. 세션 종료 요약 → State 갱신
8. 캐릭터 공방 7단계 UI
9. 테스트 3턴, 발행 가드
10. 공식 캐릭터 1명 실제 카드 기입 후 플레이테스트

**왜 이 순서인가:** 공방을 먼저 예쁘게 만들면 "카드는 있는데 세계가 없는" 데모가 되고, 채팅만 먼저 열면 "모델 말발만 있는" 캐릭터챗이 된다. 상태와 세션을 가운데 두고 앞뒤로 UI와 추론을 붙인다.

### Phase 0 완료 조건 (계획서 §9.1)

- 세션을 넘기면 캐릭터가 지난 훅을 먼저 꺼낸다
- 비밀이 조건 전에 새지 않는다
- 말투가 20턴 근처까지 버틴다
- 유저가 "채팅방"이 아니라 "회차"로 기억한다

**Phase 0가 이 4개를 통과하기 전까지 아래 Phase 1+ 항목을 앞당겨 구현하지 않는다** (계획서 §9.2 "명시적으로 빼는 것" 참고).

### Phase 1+ — 이후 순서 (계획서 §9.3, 순서 있음)

1. 공식 캐릭터 확장, 캠페인 템플릿 2~3갈래
2. 유저 창작 공방 오픈 (발행 검수 포함)
3. 로그 기반 말투 어댑터
4. 음성
5. 로그북을 시각 아카이브로
6. 제한적 멀티 (같은 월드의 비동기 흔적 정도)

## 파이프라인 (계획서 §7.6)

상세 다이어그램은 [../WORKFLOW.md](../WORKFLOW.md) 참고. 요지: Next → Nest(인증/저장/컨텍스트 조립) → FastAPI `/infer`(연기) → Nest(중계/저장) → 세션 종료 시 `/summarize` → CampaignState 갱신.
